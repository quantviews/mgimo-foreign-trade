# trade-demo: демо ИИ-чат по данным

Небольшой сервис, который даёт **демо-доступ к ИИ-ассистенту** по базе внешней
торговли: пользователь регистрируется с корпоративной почты, подтверждает адрес по
ссылке и получает несколько бесплатных диалогов, где ИИ сам обращается к нашим
данным и отвечает обычным языком.

## Сравнение с выгрузкой в Excel

Напишите обычным языком:

> Сравни экспорт нефти в Индию и Китай за последние 12 месяцев и дай выгрузку в Excel.

В ответе будут стоимость, масса и динамика индекса физического объема (fizob), а также Excel-файл. Стоимость и масса сравниваются за одинаковые месяцы факта внутри запрошенного окна. Если общий факт есть только за 11 из 12 месяцев, ответ явно назовет исключенный месяц, а не выдаст неполный период за полный.

В Excel три листа:

- **«Данные»**: выбранный помесячный ряд, включая оценки, если они запрошены.
- **«Сравнение»**: те же общие месяцы, суммы, разницы и проценты, что и в ответе.
- **«Описание»**: источники, единицы, фильтры, исключенные месяцы и методология.

Fizob показывает изменение сглаженного индекса между первым и последним общим месяцем; для каждой страны начало = 100. Это не рост суммы тоннажа за период. Индекс доступен для странового итога или одного товарного кода уровня 2/4/6. Агрегация разных физических единиц - особенность методологии проекта. Если сопоставимого индекса нет, причина будет указана, фильтры не расширяются.

Один файл ограничен 1 000 строками, 60 месяцами и 5 МБ (по тарифу лимит может быть ниже). За последние 24 часа на пользователя: до 10 новых файлов, суммарно 5 000 строк и 20 МБ. Лимит общий для чата, API и MCP. Файл доступен 7 дней; повторное скачивание не расходует квоту выгрузок.


## Как устроено

```
Пользователь → форма регистрации (корпоративный email)
             → письмо со ссылкой → /demo/verify (провижн + сессия-cookie)
             → чат /demo/chat  →  DeepSeek (function calling)
                                     ↕ вызывает наши инструменты
                             data API (trade-api) одним служебным демо-ключом
```

- **Гейт:** только рабочая почта (бесплатные и одноразовые домены отсекаются),
  плюс обязательное подтверждение владения адресом (магик-ссылка).
- **Лимит:** N ходов на пользователя (`demo_access.turn_limit`, по умолчанию 30 для новых пользователей) +
  общий дневной потолок (`demo_usage_daily`, `MGIMO_DEMO_DAILY_BUDGET`) как бэкстоп.
- **Ключи:** сырые ключи пользователей не хранятся. Инструменты дергают API одним
  служебным ключом на плане `demo` (низкий `max_rows`, только чтение). Пользователю
  свой ключ не нужен.
- **Инструменты:** те же `meta / reference / trade / fizob`, что в MCP, с тем же
  принципом «от общего к частному».

## Эндпоинты

Ссылка подтверждения входа действует 7 дней с момента создания
(`MGIMO_DEMO_VERIFY_TTL_HOURS=168`) и используется один раз. Настройка применяется
к новым ссылкам; ранее созданные сохраняют свой срок. После входа сессия действует
12 часов. Для следующего входа пользователь запрашивает новую ссылку через форму.

### Резервная отправка писем через Gmail

Основной отправитель остаётся Яндекс (`MGIMO_DEMO_SMTP_*`). При ошибке
основного SMTP сервис пробует резервный Gmail. После восстановления Яндекса
новые письма снова уходят через него. Отказ получателю не вызывает повтор
через другой сервер. Это работает для подтверждений входа и уведомлений команды.

В `/home/marcel/mgimo-foreign-trade/demo/.env` на VPS добавьте:

```dotenv
MGIMO_DEMO_FALLBACK_SMTP_HOST=smtp.gmail.com
MGIMO_DEMO_FALLBACK_SMTP_PORT=465
MGIMO_DEMO_FALLBACK_SMTP_USER=ваш_адрес@gmail.com
MGIMO_DEMO_FALLBACK_SMTP_PASSWORD=пароль_приложения
```

Основные настройки Яндекса не менять. Резерв включается только при заполненных
адресе и пароле. Используется пароль приложения Google, не пароль аккаунта.
В резервном письме `From` содержит Gmail, а `Reply-To` сохраняет адрес проекта.
После заполнения: `cd ~/mgimo-foreign-trade/demo && docker compose up -d --build`.
После пересоздания контейнера обновите DNS nginx: `docker exec landing nginx -s reload`.

Если обе отправки не удались, форма получает HTTP 503 вместо сообщения об успехе.
Неотправленная ссылка удаляется и не блокирует новую попытку дедупликацией.
Ссылки входа и пароли в журнал не записываются. Фоновая очередь повторов не реализована.
При обрыве связи после приёма письма SMTP-сервером возможна доставка двух копий
одной ссылки; подтверждение по ней остаётся одноразовым.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/demo/register` | `{email, org?}` -> проверка домена -> письмо |
| GET  | `/demo/verify?token=...` | подтверждение -> сессия -> редирект в чат |
| GET  | `/demo/me` | статус сессии и остаток ходов |
| POST | `/demo/chat` | `{messages:[...]}` -> SSE-поток ответа |
| GET  | `/demo/health` | живость |

## Переменные окружения

См. `.env.example`. Обязательные: `MGIMO_DEMO_DEEPSEEK_API_KEY`,
`MGIMO_DEMO_SERVICE_API_KEY` (ключ плана `demo`), `MGIMO_DEMO_POSTGRES_DSN`,
`MGIMO_DEMO_SESSION_SECRET`, а для писем `MGIMO_DEMO_SMTP_*` (отправитель по
умолчанию `research@fief.ru`). Без SMTP ссылка подтверждения пишется в лог (dev).

## Развёртывание (на VPS, рядом с Superset)

```bash
# 1. Миграция (создаёт план demo и таблицы demo_*)
docker exec -i superset-postgres-1 psql -U superset -d tradeapi < api/migrations/004_demo.sql

# 2. Служебный ключ на плане demo (вставить в demo/.env как SERVICE_API_KEY)
docker exec trade-api python -c "import asyncio; from app import store; \
  print(asyncio.run(store.create_user_with_token('demo-service@fief.ru', plan_code='demo')))"

# 3. Заполнить demo/.env (DeepSeek, SMTP, session secret, Postgres DSN, сеть)

# 4. Поднять сервис
cd demo && docker compose up -d --build
```

nginx проксирует `/demo/` на `trade-demo:8000` (SSE: `proxy_buffering off`, длинный
таймаут). Фронтенд чата - страница `site/demo.qmd` (за логином).

## Приватность

Тексты вопросов и подтянутые агрегаты уходят на API DeepSeek (хостинг в КНР). Для
демо по несекретной агрегированной статистике это приемлемо; в интерфейсе чата об
этом есть дисклеймер. Слой инструментов не завязан на провайдера, так что позже
можно переключиться на GigaChat/YandexGPT.


## Широкие помесячные запросы

Агент использует `export_trade`: XLSX с полным результатом выбранных фильтров и
короткая сводка в чате, вычисленная сервером. Последний месяц читается из API
перед запросом модели. По умолчанию выгрузка заканчивается этим месяцем;
`end_mode=fixed` применяется только для явно указанной пользователем конечной даты.

В XLSX сохранены исходные USD/кг, добавлены млрд USD/тонны, тип fact/pred и источник.
Лист «Описание» содержит источники, единицы измерения, фильтры и ограничения. Пропуски не подменяются нулями.
Лимит одного файла: 1 000 строк и 5 МБ, также действует размер страницы тарифа API.
Если `has_more=true`, файл не публикуется: нужно сузить фильтры. Все строки должны
помещаться в один ответ, поэтому offset-пагинация не используется.

Файлы хранятся в `api.demo_exports` (миграция `008_demo_exports.sql`).
Ссылка `/demo/exports/{uuid}` требует входа владельца и действует 7 дней.
Истёкшие файлы недоступны сразу, удаляются при следующем создании выгрузки.
Скачивание не списывает вопрос. Ключи API в ссылках отсутствуют.
Полнота выгрузки означает отсутствие усечения ответа API, а не полноту
исходной статистики по всем запрошенным странам и месяцам.


Подготовка XLSX и расчёт сводки перенесены в общий `POST /v1/exports/trade`.
Демо вызывает его сервисным API-ключом (`inline=true`), затем сохраняет готовый
XLSX в `demo_exports` с владельцем из проверенной сессии. Идентификатор пользователя
не принимается от модели. Публичная ссылка остаётся `/demo/exports/{uuid}`:
она проверяет demo-сессию, поэтому не раскрывает сервисный ключ или чужие файлы.
API-файлы хранятся отдельно в `trade_exports`; при деплое сначала применить
`009_trade_exports.sql` и обновить API, затем demo и MCP.

Обязательны `period_from` и выбор стран либо товарной группы. Максимум 60 месяцев включительно; неверные фильтры возвращают 400. Файл не обрезается автоматически.
Миграция `010_xlsx_exports.sql` добавляет бинарное хранение XLSX. Старые CSV доступны до истечения своих ссылок.
Дополнительно действует общая квота XLSX-выгрузок на аккаунт: 5 000 строк, 20 МБ (20 000 000 байт) и 10 файлов за скользящие 24 часа. API, MCP и демо суммируются; все токены одного пользователя расходуют общую квоту. Повторное скачивание существующего файла не учитывается повторно. Создание нового файла с теми же фильтрами учитывается. При превышении - 429 с Retry-After; частичный файл не создается. Квота хранится в Postgres и не сбрасывается при рестарте. Ошибка сохранения откатывает списание. Учет начинается с установки миграции 011; ранее созданные файлы задним числом не списываются.

Миграция `011_export_quota.sql`: таблицы `api.export_usage`, `api.export_delegates`, функция `api.reserve_export`. Делегирование `X-Export-User-Id` разрешено только явно зарегистрированному токену демо-сервиса; ID берется из проверенной сессии, не из аргументов модели. При замене сервисного токена требуется обновить `export_delegates`.
Ограничение относится к `/v1/exports/trade`. Обычные REST/OData-ответы регулируются своими тарифными лимитами; суммарный объем этих ответов данная квота не ограничивает.

### Сопоставимые периоды в сводке

Для нескольких стран сводка сравнивает только общие месяцы фактических наблюдений внутри запрошенного интервала. Указывает число месяцев, разницу в стоимости и массе и базу процентного сравнения. Отсутствующие страны и месяцы не считаются нулями. Прогнозы не входят в сравнение; полная таблица исходного среза остается в XLSX.
Нулевые прогнозные строки остаются в файле, но не расширяют подпись периода оценки. Проверка 15.10.2026: в июле 2026 по нефти в Индию факт national на коде 2709001000 составляет 7 269 610 000 USD; nowcast на кодах 2709000000 и 2709200000 равен нулю по стоимости и массе. Исключение пересечения в merge работает по точному коду, поэтому эти разные коды остаются. Двойного учета стоимости в этом срезе нет.

### Сравнение через общий MCP

Для сравнения стран демо вызывает `compare_trade` удалённого MCP, без отдельной копии формул. Включен `include_fizob=true`: стоимость, масса и динамика сглаженного индекса на общем периоде факта. Готовый `answer_ru` показывается без повторного пересчета моделью. Если fizob недоступен, сохраняется объяснение инструмента; ошибка MCP не заменяется выдуманным сравнением.
Адрес задается `MGIMO_DEMO_MCP_URL` (по умолчанию `https://nts.mgimo.ru/mcp`). Авторизация существующим сервисным API-ключом, завершение MCP-сессии после запроса. Сравнение не создает XLSX и не расходует квоту файлов; вопрос чата и внутренние API-запросы учитываются штатно.


### Сравнение в Excel-выгрузке

XLSX содержит листы «Данные», «Сравнение» и «Описание». При выборе 2-10 стран, одного направления и мер `stoim,netto` сравнение использует только общие месяцы факта внутри заданного окна. На листе показаны стоимость, масса, разницы и проценты относительно первой выбранной страны. Исходный помесячный ряд, включая запрошенные оценки, остается на листе «Данные».

fizob добавляется для странового итога или одного кода уровня 2/4/6. Каждая страна приведена к собственной начальной точке = 100; динамика считается между крайними общими месяцами. Это сглаженный индекс, а не рост суммы тоннажа за период. Агрегация разных физических единиц - особенность методологии проекта. При недостатке индексов или дополнительных фильтрах по источнику/единице причина отсутствия fizob указана явно, фильтры не расширяются.

Лист «Описание» содержит источники, единицы, фильтры, общие и исключенные месяцы и формулы. Ограничения файлов и суточные квоты сохранены: производные строки сравнения не расширяют исходный срез, размер всего XLSX учитывается в квоте. Старые файлы не меняются, для нового листа нужно создать новую выгрузку. Расчет общий с MCP `compare_trade` через `POST /v1/compare/trade`.

Если вопрос одновременно просит сравнение и Excel, чат завершает оба действия перед ответом. Расчет сравнения берется из результата API выгрузки, по которому создан XLSX; модель формулирует выводы по этим проверенным значениям. При ошибке или превышении квоты чат сообщает, что файл не создан, и не придумывает ссылку.


### Ошибки выгрузки и списание вопросов

С 15 октября 2026 года названия товаров в Excel согласуются с группировкой: для единственного выбранного кода его уровень добавляется автоматически. Необязательное название, которое потребовало бы детализации агрегата по нескольким кодам, не запрашивается.

Ответы API 400 сохраняются в серверном журнале с исходной причиной. Пользователь получает сообщение по типу ошибки, а не универсальное сообщение о 60 месяцах. Сбои выгрузки передаются как ошибки чата.

Личный вопрос резервируется перед запуском и возвращается при ошибке, пустом результате или незавершенном ответе. Успешный ответ списывает один вопрос. Общий дневной бюджет продолжает учитывать попытки, поскольку внешняя модель могла уже выполнить запрос. Пустые сообщения отклоняются до резервирования.

Регрессионные проверки: `demo/tests/test_export_failures.py`. На проде проверены исходный вопрос об импорте автомобилей из Китая за последние 12 доступных месяцев и прежнее ошибочное сочетание `include=tnved4_name`, `group_by=period,edizm`.


### Точность количества и персональные исключения

Дробные количества, включая оценки Comtrade, сохраняют дробную часть в чате и Excel. В таблице чата оцененное количество отмечается отдельно от nowcast.

Миграция `012_export_quota_exemptions.sql` добавляет управляемые администратором исключения суточной квоты в `api.export_quota_exemptions`. Исключение привязано к пользователю, а не к общему токену демо. Суточные пределы количества файлов, строк и байтов для него отключаются; размер одного файла и журнал выгрузок сохраняются. В ответе API это отражается как `daily_limits.exempt=true`. Для остальных пользователей квоты не меняются.


### Аналитические ответы и уточнения

После создания Excel модель получает проверенную сводку и ограниченный набор данных, затем отвечает по существу вопроса. Ссылку на файл добавляет сервис. Успешное создание выгрузки больше не завершает агент шаблонным текстом.

Уточнение «давай отдельно по месяцам и динамику» использует историю для определения среза и получает данные через `trade`. Оно не создает новый Excel, если последняя реплика не просит файл. Автоматическая выгрузка длинного ряда также отключена без такой просьбы.

`monthly_evidence` рассчитывает абсолютные и процентные изменения к предыдущему календарному месяцу и тому же месяцу прошлого года внутри одной страны, единицы, источника и типа данных. Пропуски, неположительная база и неоднозначные дубли не превращаются в нулевой рост. Для 12 месяцев агент показывает таблицу и краткие выводы. Лимит аналитического ответа задает `analytical_output_tokens` (по умолчанию 2800); обрыв по лимиту остается ошибкой, а не полным ответом.

### Месячная динамика год к году

Для короткого помесячного ответа сервис дополнительно запрашивает предыдущие 12 месяцев с теми же фильтрами. Для короткого помесячного ответа они служат базой расчета, а показывается запрошенный период. Отдельный режим разбора год к году с Excel сохраняет оба периода, как описано ниже. Стоимость и количество сравниваются с тем же месяцем предыдущего года, масса в чате показывается в тыс. тонн (NETTO / 1 000 000). Значения изменений рассчитываются кодом, а модель формулирует выводы.

Сравнение выполняется внутри одного источника, типа данных и единицы измерения. Для nowcast, отсутствующей или нулевой базы процент не рассчитывается. Если базу не удалось получить полностью, ответ явно сообщает об отсутствии сопоставимой динамики. Ранее созданные Excel-файлы не изменяются.

### От общего к частному

На вопросы о причинах динамики агент сначала проверяет общий итог и сопоставимость периодов, затем разбирает подкатегории на следующем уровне кодов. Показывает доли сейчас и год назад, абсолютное изменение и вклад в темп роста родительской группы (п.п.). Сумма подкатегорий сверяется с общим итогом; неполный срез не выдается за полное объяснение. Количество сравнивается внутри одинаковых единиц, индексы fizob не складываются.

Пример: «Как изменился импорт легковых автомобилей (8703) из Китая за последние 12 доступных месяцев год к году? Объясни за счет каких подкатегорий: доли и вклад в изменение». Для простой выгрузки дополнительный разбор не запускается.

Расчеты выполняет общий MCP-инструмент `explain_trade(strana="CN", napr="im", code="8703", months=12)`. Он проверяет наличие одинаковых календарных месяцев в обоих годах и сверяет суммы подкатегорий с родительскими итогами. Отсутствующая категория не заменяется нулем: ее часть изменения остается нераспределенной. Разложение относится к стоимости; количество и fizob не выводятся из денежных долей. Названия кодов не генерируются инструментом: агент должен использовать проверенный справочник или показывать коды.

Названия подкатегорий приходят из русского справочника базы вместе с кодами. Агент использует их без повторного перевода. Для гибридных групп 870340, 870350, 870360 и 870370 исправлены шестизначные подписи и укрупненные записи с нулями справа. Английский обход удален. Правки закреплены в metadata/translations/name_overrides.json через exact_level, поэтому следующие сборки их сохраняют; более подробные национальные коды не меняются. Ранее сформированные Excel-файлы остаются прежними, новые получают обновленный справочник.

### Разбор год к году и исходные данные в Excel

Пример для «Спросить ИИ»:

> Как изменился импорт легковых автомобилей (8703) из Китая за последние 12 доступных месяцев год к году? Объясни доли и вклад подкатегорий. Дай исходные данные обоих периодов в Excel, факт и nowcast отдельно.

Чат связывает выгрузку с периодами и источником `explain_trade`. В файле:

- «Факт»: доступные исходные помесячные строки текущего периода и тех же месяцев годом ранее. `comparison_period=current` / `previous` различает окна.
- «Nowcast»: модельные оценки проекта отдельно, без включения в фактические итоги.
- «Описание»: границы периодов, источники, единицы, фильтры и правила интерпретации.

Доли и вклады рассчитаны для ответа, в Excel сохраняются исходные данные для воспроизведения расчетов. В чате допустимы сокращенные названия с точным кодом; Excel сохраняет русские названия из базы.

Если факта за один из месяцев нет, файл сохраняет доступные наблюдения обоих окон, но ответ не рассчитывает полный итог год к году и перечисляет пропуски. Период не сдвигается незаметно. Наличие всех месяцев само по себе не гарантирует полноту товарного покрытия. Неизвестные количество и масса остаются пустыми; сумму известных значений нельзя представлять как полный итог.

`SOURCE=comtrade`, `TYPE=fact` может содержать оценки физических показателей самого источника. Они сохраняются с признаками качества и не относятся к nowcast проекта (`TYPE=pred` или `SOURCE=nowcast`). Выбранная национальная статистика не дополняется Comtrade молча.

Оба периода и все строки nowcast учитываются в лимитах файла и суточной квоте. Старые файлы не меняются; нужно сформировать новую выгрузку.

Повторный вызов выгрузки в одном ходе возвращает уже подготовленный файл, не создает второй и не расходует повторно квоту. Аналитические инструменты выполняются перед экспортом в одном пакете вызовов. Внешняя модель, вернувшая служебную разметку DSML вместо ответа, получает одну повторную попытку; повторный сбой становится ошибкой чата.

Проверка 15 октября 2026 года: для автомобилей из Индии окно сентябрь 2025 - август 2026 содержит 11 месяцев национального факта, прошлогоднее окно - 12. В проверенном файле 47 фактических строк и 4 строки nowcast. Масса отсутствует во всех фактических строках, количество - в 45 из 47; полные физические итоги не публикуются. Это результат конкретного среза и версии базы, а не постоянное ограничение по стране.

Регрессионные тесты: `demo/tests/test_india_export_coverage.py`, `demo/tests/test_mcp_comparison.py`, `api/tests/test_exports.py`.

### Порядок аналитического ответа

Ответ начинается с изменения агрегата и главных драйверов, затем показывает доли и вклад подкатегорий, изменение структуры. Краткая справка об источнике и существенных ограничениях идет после анализа. Ограничение, которое делает основной вывод невозможным, сообщается сразу. Источник называется прямо, например «таможенная статистика Китая»; перечень исключенных источников и внутренние поля API не повторяются без необходимости. Сокращенные названия допустимы с точным кодом, в Excel сохраняется справочник базы. Проверки полноты и разделение факта, оценок источника и nowcast остаются обязательными.

### Топ товарных групп

Запрос топа по стоимости использует полные агрегаты ТН ВЭД-2 с фактическими данными. Внутри сервиса получаются все группы (с проверкой `has_more`), затем рассчитываются общий объем, доли лидеров и сумма остальных групп. В чат передается запрошенный топ, а не все строки. Выбор топ-N не является ошибкой неполных данных; настоящий усеченный ответ API по-прежнему блокируется. Фактические месяцы и источники проверяются отдельным агрегатом. Excel для такого вопроса не требуется.

Регрессионная проверка: `demo/tests/test_rank_chapters.py`.

### Предупреждения по показателям

Область предупреждений о качестве: связывай каждый флаг только с проверяемым показателем. Предупреждение о массе относится к массе и производным от нее (цена за кг, динамика массы); предупреждение о количестве или единице относится к количеству и производным от него. Низкая масса на транспортное средство сама по себе не доказывает ошибку стоимости. Стоимость, ее динамику и доли по стоимости ставь под сомнение только при отдельном свидетельстве проблемы стоимости или покрытия. Для топа по стоимости не добавляй оговорку о массе, если масса не используется в выводах. Не скрывай соответствующие флаги при ответах о физических показателях. Если предупреждение неоднозначно, не расширяй его смысл на другие показатели.

### Поиск товара по свободному описанию

Перед обзором товара без явно заданного кода агент вызывает `search_products`: поиск по русскому справочнику, общий с MCP. Уровень выбирается по запросу: 2 знака для широкой главы, 4 для товарной группы, 6 для конкретного подтипа. «Мужское трикотажное белье» сопоставляется с названием 6107; «белье» требует уточнения назначения и исполнения. При неоднозначности агент задает вопрос до получения торговых данных и создания файла. Уточнение используется вместе с историей диалога. Поиск кандидатов не заменяет подтверждение их смысла по справочнику.

После выбора кода `product_overview` возвращает название, партнеров, доли и динамику на сопоставимом составе. Числовой ответ проверяется сервисом перед публикацией.
