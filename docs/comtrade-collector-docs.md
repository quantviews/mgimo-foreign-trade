# Документация по `comtrade_collector.py` — загрузка данных UN Comtrade

## 1. Назначение

`src/collectors/comtrade_collector.py` скачивает помесячные данные UN Comtrade о
торговле стран мира **с Россией** и складывает их в `data_raw/comtrade_data/` в
том формате, который читает `src/merge_comtrade_to_duckdb.py`.

Это зеркальные данные: страна-репортёр отчитывается о своём экспорте (`X`) и
импорте (`M`), партнёр всегда Россия (код M49 `643`). При сборке
`comtrade.db` направления переворачиваются в российскую перспективу
(`X` → `ИМ`, `M` → `ЭК`), см. `docs/merge-comtrade-to-duckdb-docs.md`.

Скрипт заменяет `MirrorTrade/comtrade-data.py`, который жил в соседнем
репозитории, писал CSV и требовал ручного переноса. Отличия перечислены в
разделе 10.

## 2. Ключ подписки

Ключ читается из переменной окружения `COMTRADE_API_KEY`, а при её отсутствии —
из `.env` в корне проекта (файл под `.gitignore`):

```
COMTRADE_API_KEY=ваш_ключ
```

Ключ выдаётся в личном кабинете UN Comtrade. Проверить его можно одной строкой:

```bash
curl -s "https://comtradeapi.un.org/data/v1/get/C/M/HS?reporterCode=156&period=202401&flowCode=X&partnerCode=643&cmdCode=ALL&maxRecords=10&includeDesc=False&subscription-key=КЛЮЧ" | head -c 200
```

Ответы различаются по смыслу:

| Ответ | Что означает |
|---|---|
| `HTTP 200` с массивом `data` | ключ рабочий |
| `Access denied due to **missing** subscription key` | ключ не дошёл до API |
| `Access denied due to **invalid** subscription key … active subscription` | ключ доставлен и отвергнут: истёк, перевыпущен или подписка неактивна |

Ключи в кабинете идут парами (primary и secondary) — если первый перестал
работать, стоит проверить второй, прежде чем перевыпускать.

**Справочники ключа не требуют.** Список стран-репортёров и справочник
доступности данных отдаются публично, поэтому режим `--check` (раздел 5)
работает без ключа и без расхода квоты.

## 3. Использование

```bash
# что устарело — без ключа, без загрузки, без расхода квоты
python src/collectors/comtrade_collector.py --check

# догрузить недостающие месяцы
python src/collectors/comtrade_collector.py

# плюс перекачать страны, пересмотревшие отчётность
python src/collectors/comtrade_collector.py --refresh

# ограничить прогон бюджетом запросов (бесплатный тариф)
python src/collectors/comtrade_collector.py --refresh --max-requests 130

# точечно, один месяц
python src/collectors/comtrade_collector.py --refresh --period 2026-06
```

| Аргумент | Смысл |
|---|---|
| `--start-year` | с какого года считать периоды, по умолчанию 2019 |
| `--period YYYY-MM` | ограничиться месяцем; можно повторять |
| `--refresh` | помимо недостающих месяцев обновить пересмотренные страны |
| `--check` | только отчёт об устаревании, ничего не качает |
| `--dry-run` | показать план и выйти |
| `--max-requests N` | остановиться, израсходовав N запросов |
| `--batch-size N` | стран в одном запросе, по умолчанию 8 |

Коды возврата: `0` — успех, `2` — прогон остановлен по исчерпании квоты API или
заданного бюджета (это штатная ситуация, следующий запуск продолжит с того же
места).

## 4. Что скачивается и куда

```
data_raw/comtrade_data/
├── 2019-01.parquet
├── 2019-02.parquet
├── …
├── 2026-07.parquet
└── _manifest.json      ← служебный, см. раздел 5
```

Один файл на месяц, схема — 47 колонок Comtrade как есть (`includeDesc=False`,
описания не запрашиваются, они подтягиваются из справочников проекта).

**Текущий месяц не скачивается.** За него данные заведомо неполны, а файл потом
не переписывался бы: единственным правилом возобновления в исходном скрипте было
«файл существует». Так в репозитории появились `2026-05.parquet` с семью
странами и `2026-06.parquet` с одной, замороженные в момент загрузки.

**Схема нового файла приводится к схеме соседних.** При `includeDesc=False`
часть колонок приходит пустой, и pandas выводит их тип по содержимому — у одного
месяца `object`, у другого `float64`. Сборка `comtrade.db` склеивает файлы через
`UNION ALL` и на таком расхождении падает.

## 5. Пересмотры отчётности и манифест

Страны досылают и правят данные годами. Январь 2024 у Андорры впервые
опубликован 26.02.2024, а последний раз — 03.08.2026. Замер по файлам проекта на
момент внедрения:

| месяц | стран в файле | доступно | пересмотрели после загрузки |
|---|---|---|---|
| 2019-06 | 119 | 129 | 1 |
| 2023-06 | 120 | 120 | 9 |
| 2025-06 | 68 | 95 | 51 |

Правило «перекачивать последние N месяцев» тут не работает: глубина пересмотра
разная от месяца к месяцу, а пропуски встречаются и в 2019 году.

Поэтому рядом с parquet лежит `_manifest.json`: по каждому месяцу — какие страны
попали в файл и какой у их выгрузки был `datasetChecksum`.

```json
{
  "2026-06": {
    "downloaded_at": "2026-08-29T14:51:06",
    "rows": 114790,
    "reporters": {
      "156": {"checksum": "-1403321520", "lastReleased": "2026-08-03T19:51:21.7333333"}
    }
  }
}
```

Перед обновлением манифест сверяется со справочником доступности. Страна
попадает в перекачку, если:

* её данные доступны, но в файле их нет — месяц скачали до того, как она
  отчиталась, либо прошлый запрос к ней не прошёл;
* её `datasetChecksum` изменился с момента загрузки.

Перекачиваются только такие страны, и их строки **замещаются** в существующем
файле: остальные остаются нетронутыми. Страна, отозвавшая отчёт, теряет свои
старые строки, а не сохраняет их.

В манифест попадают все опрошенные страны, а не только давшие строки. Страна
может отчитываться в Comtrade, не торгуя с Россией: в parquet её не будет, и без
записи в манифесте она выглядела бы неопрошенной в каждом следующем прогоне.

Для файлов, скачанных до появления манифеста, чек-сумм нет, и признаком служит
`lastReleased` позже времени модификации файла. Это грубее (переписывание файла
обнуляет признак), но не требует перекачивать всё ради первого прогона.

## 6. Расход запросов на бесплатном тарифе

Бесплатная подписка ограничена числом обращений в сутки. API принимает списки и
в `reporterCode`, и в `flowCode`, поэтому одна пачка стран запрашивается сразу по
экспорту и импорту:

| стран в запросе | запросов на полный догон 90 месяцев |
|---|---|
| 1 страна, 1 поток (исходный скрипт) | 4 142 |
| 1 страна, оба потока | 2 071 |
| 4 страны | 554 |
| **8 стран (по умолчанию)** | **301** |

`--max-requests N` останавливает прогон по исчерпании бюджета: манифест
дописывается, код возврата 2. Порядок обхода — сначала недостающие месяцы, затем
самые свежие, чтобы ограниченный бюджет тратился на нужное.

Месяц никогда не записывается наполовину: частичный файл выглядел бы для
следующего прогона готовым.

Примерный график догона накопившегося долга:

```bash
# день 1 — свежее и самое дырявое (2025-2026)
python src/collectors/comtrade_collector.py --refresh --start-year 2025 --max-requests 130
# день 2 — середина
python src/collectors/comtrade_collector.py --refresh --start-year 2023 --max-requests 130
# день 3 — остаток по всей истории
python src/collectors/comtrade_collector.py --refresh --max-requests 130
```

Дальше достаточно раз в неделю `--refresh --max-requests 50`.

Остаток суточной квоты API в заголовках ответа **не сообщает** — бюджет
задаётся вручную исходя из тарифа.

## 7. Обрезка ответа

`maxRecords` — параметр запроса, а не предел сервера, и он режет ответ молча: в
теле нет признака обрезки, а поле `count` равно числу возвращённых строк, а не
настоящему.

Исходный скрипт запрашивал с `maxRecords=50000`, и экспорт Германии упирался
ровно в 50 000 строк в 38 парах «страна-месяц», теряя по 7-11 тысяч записей
(2020-02: в файле 50 000, на самом деле 61 078).

Сейчас лимит 250 000, а совпадение длины ответа с лимитом трактуется как
обрезка: пачка делится пополам и запрашивается заново. Пачку из одной страны
делить некуда — такой случай остаётся в логе предупреждением:

```
страна 276 за 202002 вернула 250000 строк — предел запроса, данные обрезаны
```

Найти уже обрезанные месяцы в каталоге:

```sql
SELECT regexp_extract(filename, '([0-9]{4}-[0-9]{2})\.parquet', 1) AS month,
       reporterCode, flowCode, count(*) n
FROM read_parquet('data_raw/comtrade_data/*.parquet', filename=true)
GROUP BY 1, 2, 3
HAVING count(*) IN (50000, 250000);
```

## 8. Место в пайплайне

```
comtrade_collector.py  →  data_raw/comtrade_data/*.parquet
                                   ↓
                       merge_comtrade_to_duckdb.py  →  db/comtrade.db
                                   ↓
                       merge_processed_data --include-comtrade
                                   ↓
                       db/unified_trade_data.duckdb
```

Оба первых шага вызываются из flow:

```python
from src.orchestration.flows import mgimo_full_refresh
mgimo_full_refresh(collect_comtrade=True, refresh_comtrade=True)
```

`rebuild_comtrade_db` по умолчанию `None`, что означает «пересобрать вместе со
скачиванием». Свежие parquet при старой `comtrade.db` — тихий отказ: merge
отработает и молча возьмёт прежние данные.

## 9. Диагностика

| Симптом | Причина и что делать |
|---|---|
| `COMTRADE_API_KEY не найден` | нет ключа в окружении и в `.env` |
| `invalid subscription key` | ключ истёк или перевыпущен, см. раздел 2 |
| код возврата 2 | бюджет или квота исчерпаны — это штатно, запустить снова |
| `данные не предоставила ни одна страна` | справочник доступности пуст за месяц; для свежих месяцев нормально |
| `предел запроса, данные обрезаны` | одна страна не помещается в `MAX_RECORDS`, нужно поднимать константу |
| Месяц скачался, но данных мало | сверить с `--check`: возможно, страны ещё не отчитались |

Исходный скрипт при ошибке запроса делал `continue` и в конце сообщал «данные не
найдены ни у одного репортёра» — внешне это неотличимо от пустого месяца. Здесь
ошибки логируются отдельно, а исчерпание квоты останавливает прогон явно.

## 10. Отличия от `MirrorTrade/comtrade-data.py`

| | Исходный скрипт | Здесь |
|---|---|---|
| Ключ | зашит в исходник | `COMTRADE_API_KEY` из окружения или `.env` |
| Формат | CSV, затем ручная конвертация | сразу parquet в `data_raw/comtrade_data/` |
| Схема | как выведет pandas | приводится к схеме соседних файлов |
| Текущий месяц | качается и замерзает частичным | не качается |
| Пересмотры | не отслеживаются | манифест + `datasetChecksum` |
| Запросов на догон | 4 142 | 301 |
| `maxRecords` | 50 000, режет молча | 250 000 + обнаружение обрезки |
| Исчерпание квоты | `exit()` посреди месяца | штатная остановка с кодом 2 |
| Оркестрация | запуск вручную из другого репозитория | шаг Prefect flow |
