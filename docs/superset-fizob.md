# Вкладка «Физобъемы»

Вкладка использует общую с месячными бюллетенями витрину:
`sql/fizob_bulletin.sql`. В ней представлены все 141 страны с расчетом fizob,
уровни 0 (страна), 2, 4 и 6 знаков ТН ВЭД, а также готовый агрегат `ALL`
на уровнях 2/4/6. Общий итог ALL уровня 0 рассчитывается при локальной сборке
витрины. Бюллетени выбирают из той же витрины Китай, Индию и Турцию.

Показатель `yoy = fizob(t) / fizob(t - 12 месяцев) - 1` хранится долей,
а в графике показывается в процентах с одним десятичным знаком.
Это изменение сглаженного индекса: исходный расчет использует
12-месячные скользящие средние. Агрегация разнородных физических единиц
является особенностью методологии индекса.

Предыдущий год сопоставляется по календарной дате, стране, направлению,
уровню и коду. Фильтр отображаемого периода применяется после расчета.
Отсутствующий или нулевой знаменатель дает NULL. Нулевой числитель при
положительном знаменателе дает -100%. Разные страны и товарные коды
не усредняются в один индекс.

## Интерфейс

- По умолчанию: «Все страны в базе» и «Все товары».
- Выбор любой доступной страны или пункта «Все страны в базе».
- Период по умолчанию: последние 60 месяцев снимка (пять лет), до последнего
  доступного месяца данных. Диапазон можно изменить вручную.
- Детализация: одна страна и одна товарная группа с кодом и названием.
  Пункт «Все товары» доступен для отдельной страны и для ALL.
- Над детализацией показаны выбранная страна и полное название товара с кодом.
- Импорт и экспорт в детализации показаны на отдельных графиках с независимыми
  шкалами; таблица помесячных значений использует те же фильтры.
- Общая цветовая подпись заменяет повторяющиеся легенды с кнопками «Всё/Обратить».
- Прежние товарные фильтры других вкладок на новые графики не влияют.
- Рядом с графиками показаны стоимость по имеющимся фактическим записям
  за последние 12 месяцев выбранного периода и предыдущие 12 месяцев,
  границы окон, число месяцев с записями и последний месяц источника.
  Отсутствующая стоимость остается NULL, наблюдаемый ноль сохраняется.
- Число месяцев с записями не является доказательством полного охвата стран.
  Сравнивать изменение стоимости как строго сопоставимый темп по этой таблице
  без проверки состава источников нельзя.

## Методология режима «Все страны»

Используется сохраненный `STRANA='ALL'` из `query_fizob_all_level`
в `src/fizob_queries.R`. На этом уровне складываются `netto_12`, взвешенные
по долям `stoim_12` в выбранной товарной группе по всем странам.
Это предусмотренный методологией расчет, не сумма и не среднее
нормированных страновых индексов.

Проверено совпадение всех 1 286 712 строк ALL с результатами R в
`fizob_2/4/6.parquet`; максимальная разница равна нулю.
Г/г вычисляется по одному коду и направлению между одинаковыми месяцами.

Для ALL уровня 0 витрина расширяет формулу странового итога из R:
`raw_country = fizob * fizob_bp`, `raw_all = sum(raw_country)`.
Общий ряд нормируется на среднее первых 12 календарных месяцев,
отдельно для импорта и экспорта. Темп г/г равен отношению общих расчетных
объемов в одинаковых месяцах с разницей в год минус единица.
Это агрегация исходного расчетного показателя страновых итогов,
а не сумма или среднее нормированных индексов. Она сохраняет выбор
физической единицы из страновой методологии; общий индекс не измеряется в тоннах.
Существующие ALL-группы 2/4/6 продолжают использовать свою формулу R.
Если основной расчет в будущем предоставит готовый ALL уровня 0,
витрина использует его без повторного добавления.
Взвешенный показатель трех основных партнеров из заголовка общего бюллетеня
не подставляется вместо ALL.

Идентификаторы фильтров страны и товара обновлены при смене стартового выбора.
Это не дает прежним сохраненным значениям «Китай / 8703» перекрывать новые
значения по умолчанию. Последующие пользовательские выборы Superset сохраняет
обычным образом.

`sql/fizob_trade_context.sql` добавляет денежный размер потока и прошлогодней
базы. В расчет стоимости входят только TYPE=fact. ALL формируется по фактам
один раз, без повторного сложения строк разных товарных уровней и nowcast.

## Обновление и проверки

Выполнять обработку только локально:

```powershell
python scripts/build_fizob_bulletin.py
python -m pytest tests/test_fizob_bulletin.py
```

Для проверки добавления общего итога перед заменой текущего снимка:
`python scripts/build_fizob_bulletin.py --output site/data/fizob_bulletin_total.parquet`,
затем `python scripts/check_fizob_all_total.py`.
Проверка сверяет общий индекс с исходным `fizob_total.parquet`, г/г, суммы
стоимости с фактами DuckDB и контрольные суммы прежних рядов.
Отчет: `tmp/fizob-all-total-validation.json`.

Снимок: `site/data/fizob_bulletin.parquet`.
Отчет: `site/data/fizob_bulletin.validation.json`.
Проверяются уникальность ключа и совпадение странового г/г с прежним
расчетом бюллетеней. Скрипты подготовки общего и страновых бюллетеней
читают тот же SQL через `site/read_fizob_bulletin.R`.

На VPS передается готовый снимок в `/srv/parquet/fizob_bulletin.parquet`.
В контейнере Superset он доступен как `/data/parquet/fizob_bulletin.parquet`.
Два виртуальных датасета разделяют страновые итоги и товарные группы.
Пересборка основной DuckDB и перезапуск сервисов для этого не нужны.

Перед изменениями сохранить PostgreSQL и конфигурацию Superset.
`scripts/configure_superset_fizob.py` запускается внутри контейнера Superset:
он настраивает датасеты, пять элементов с данными и фильтры вкладки «Физобъемы»,
не пересчитывая данные. Старые графики сохраняются вне этой вкладки.
Повторный запуск обновляет созданные объекты.

При публикации бюллетеней также локально рендерятся HTML и PDF.
Проверять не только формулу, но и актуальность снимков: старый бюллетень
может содержать прежнюю версию fizob.

## Проверка скачка по автомобилям, 20 октября 2026

`python scripts/check_fizob_cars_china.py` сверяет исходные CSV за март 2024 -
февраль 2026 с фактическими строками DuckDB, затем локально воспроизводит
расчет индекса на небольшом срезе. Отчет: `tmp/fizob-cars-china-audit.json`.

Скачок относится к **экспорту России в Китай**, код 8703.
В феврале 2026 fizob = 0,6061213330, годом ранее = 0,0691825768.
Их отношение дает **+776,1185% г/г**; расчет воспроизведен из исходных записей.

| Скользящее окно | Количество в исходных записях | Стоимость, долл. | Вес электромобилей 87038010 |
|---|---:|---:|---:|
| Март 2024 - февраль 2025 | 6 шт. | 167 943 | 9,2% |
| Март 2025 - февраль 2026 | 32 шт. | 1 100 766 | 75,1% |

Индекс учитывает скользящие средние по товарным кодам и меняющиеся стоимостные
веса. Поэтому +776,1% не равно темпу количества 32/6 - 1.
Скачок связан с малой базой и изменением состава редких поставок.
В источнике за февраль 2025 есть одна машина, за февраль 2026 - шесть.
Проверено совпадение 15 исходных строк с DuckDB за оба годовых окна.
Пропуски исходных записей заполняются нулями в действующем алгоритме fizob;
эта техническая операция не доказывает отсутствие торговли в пропущенные месяцы.
Формулы индекса и исходные данные в рамках исправления оформления не менялись.
