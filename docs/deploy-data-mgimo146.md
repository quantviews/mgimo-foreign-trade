# Публикация готового выпуска на сервере 146

Инструкция для Windows PowerShell. Скрипт передаёт уже рассчитанные данные и бюллетени с ПК на сервер МГИМО `172.17.0.146` (`prod-146`). Расчёты на сервере не запускаются.

**Текущий пакет:** локальный выпуск `20261119-india` с проверенными дополнениями массы Индии, пересмотрами нефти и обновленными бюллетенями, данные по сентябрь 2026. Архив: `tmp/publish-146-20261119-india/release.tar.gz` (816 143 382 байта, 55 файлов). SHA-256: `a35cb34be7dba8e12d4859611bc3c51997dfb7e3993afe93d5245b086bf4a6ff`. Распаковка и контрольные суммы проверены локально серверным проверяющим кодом. Старые пакеты сохранены отдельно. Публикация этого выпуска на 146 пока не выполнялась.

Скрипт: `deploy/mgimo146/publish.ps1`. Серверный помощник: `deploy/mgimo146/publish_remote.py`.

## 1. Перед запуском

1. Подключите Cisco AnyConnect к сети МГИМО.
2. Убедитесь, что ПК не перейдёт в спящий режим. Оставьте VPN и терминал открытыми до окончания выкладки.
3. Выберите время, когда допустим краткий перерыв в работе API, MCP, ИИ-чата и Superset. Передача архива идёт при работающих сервисах; остановка начинается после проверки загруженного пакета.
4. На ПК должны быть команды `ssh` и `scp` из OpenSSH. Вход `stp` на сервер должен работать по ключу. Скрипт использует `BatchMode=yes` и не запрашивает пароль.

Откройте PowerShell и перейдите в проект:

```powershell
Set-Location 'F:\Yandex.Disk\HSE\mgimo-foreign_trade'
```

Проверка сети и входа:

```powershell
Test-NetConnection 172.17.0.146 -Port 22
ssh -o BatchMode=yes -o ConnectTimeout=15 stp@172.17.0.146 "hostname; whoami; df -h /"
```

Ожидается `TcpTestSucceeded : True`, имя `prod-146` и пользователь `stp`. При первом подключении OpenSSH может попросить подтвердить ключ сервера: сначала сверьте его отпечаток с администратором. Проверка ключа сервера в скрипте не отключается.

На сервере нужны Python 3, Docker, curl и действующий стек проекта. Пользователь `stp` должен иметь доступ к Docker. Пароль sudo не нужен: копирование в служебные каталоги выполняется временным контейнером на уже установленном образе Superset.

## 2. Проверочный запуск

```powershell
.\deploy\mgimo146\publish.ps1 -CheckOnly
```

Проверяются SSH, имя сервера, доступ к Docker, наличие локального архива; выводятся свободное место и SHA256 архива. Файлы на сервер не передаются, сервисы не останавливаются.

Это предварительная проверка соединения. Проверка содержимого архива, резервирования и сервисов выполняется при настоящей выкладке.

Если PowerShell запрещает запуск локального скрипта, можно выполнить только этот запуск так:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\mgimo146\publish.ps1 -CheckOnly
```

Постоянно изменять политику выполнения не требуется.

## 3. Выкладка

```powershell
.\deploy\mgimo146\publish.ps1
```

При необходимости указать другой заранее подготовленный совместимый пакет:

```powershell
.\deploy\mgimo146\publish.ps1 -Package 'F:\путь\к\release.tar.gz'
```

Произвольный ZIP или архив всей папки проекта не подходит. Пакет должен содержать `manifest.json` с размерами и SHA256 каждого файла и только разрешённые пути данных и бюллетеней. Новый пакет готовится после локальной пересборки и проверки выпуска. Скрипт не собирает пакет и не обновляет его автоматически.

### Подготовка нового пакета локально

После пересборки и проверок (без подключения к серверу):

```powershell
python deploy/mgimo146/prepare_package.py --output tmp/publish-146-20261119-india --validation-dir tmp/release-20261119-india --release 20261119-india
```

Указанная папка текущего выпуска уже существует. Для повторной подготовки выберите **новую** папку: скрипт не перезаписывает готовые пакеты. Он сверяет базу и витрину с отчетом локальной установки, PDF с отчетом проверки, включает только разрешенные файлы и проверяет архив через `unpack` серверного помощника. В папке остаются `manifest.json`, `package-check.json`, архив и проверенная распакованная копия `payload`.

### Что происходит

1. Проверяются сервер и локальный архив.
2. Создаётся отдельный каталог `/home/stp/mgimo-release-ГГГГММДД-ЧЧММСС` с закрытым доступом. Его путь выводится в терминале - сохраните его для отката.
3. Передаются архив и два Python-скрипта. Ключи SSH, `.env`, TLS-сертификаты и пароли не передаются.
4. Сервер сверяет SHA256 архива, безопасно распаковывает его, сверяет состав, размеры и контрольные суммы файлов. Проверяется запас места для распаковки, прежней версии и временных копий.
5. Проверяется наличие шести работающих контейнеров: `trade-api`, `trade-demo`, `trade-mcp` и сервисов `superset`, `worker`, `beat` проекта `mgimo-superset`. При другой конфигурации скрипт останавливается до изменений.
6. Останавливаются эти шесть потребителей данных. PostgreSQL, Redis и nginx продолжают работать.
7. Сохраняются прежние версии всех заменяемых файлов и их контрольные суммы в подкаталог `backup` серверного каталога выпуска. Фиксируется также, какие файлы раньше отсутствовали.
8. Готовая база устанавливается в `/srv/duckdb/unified_trade_data.duckdb`, витрина - в `/srv/parquet/fizob_bulletin.parquet`. Бюллетени и ресурсы устанавливаются в каталог `site` внутри `/opt/mgimo-landing/mgimo-landing`. Каждый файл копируется через временную копию с проверкой SHA256 и атомарной заменой.
9. Запускаются прежние контейнеры, очищается только кеш результатов графиков `superset_data_*` в Redis DB 1.
10. Проверяются API, демо и Superset, метаданные новой базы, авторизованная XLSX-выгрузка автомобилей из Китая, MCP и содержимое HTML/PDF через HTTPS с проверкой сертификата.

Проверка Excel расходует одну обычную квоту внутреннего сервиса. Письма не отправляются, запросы к модели ИИ не выполняются. Проверка демо подтверждает доступность процесса, но не заменяет проверку диалога с моделью.

Скрипт также исправляет ссылки меню на страновые бюллетени: `bulletin_*_pdf.qmd` заменяется на `bulletin_*_pdf.html` для Китая, Индии и Турции. Проверяются готовые страницы пакета и существующие HTML-страницы в каталоге `site`. В существующих страницах изменяются только эти ссылки; их прежние версии сохраняются в `backup/navigation`, а список - в `backup/navigation.json`. Откат восстанавливает исходные страницы. После установки содержимое исправленных страниц сверяется через HTTPS. Пакет без HTML-бюллетеней всех трех стран отклоняется до остановки сервисов.

Это исправление работает и с ранее подготовленным пакетом от 18 ноября: обновленный серверный помощник передается при каждом запуске `publish.ps1`. Старый адрес `.qmd` сам по себе не становится страницей; нужно перейти по исправленному меню или адресу `.html`.

Код приложений, Docker-образы, конфигурации, сертификаты и служебная база PostgreSQL не обновляются. Резервная копия здесь относится к заменяемым файлам выпуска и исправленным страницам меню, а не ко всему серверу.

## 5. Откат

При ошибке установки или последующих проверок скрипт пытается восстановить прежние файлы, запустить сервисы, очистить кеш графиков и проверить их состояние. Ошибка всё равно выводится в терминал: её нельзя считать успешной публикацией.

Для ручного отката используйте точный путь, показанный при выкладке:

```powershell
.\deploy\mgimo146\publish.ps1 -RollbackStage '/home/stp/mgimo-release-20261118-210000'
```

`20261118-210000` здесь пример, замените его на свой каталог. Контрольные суммы всех резервных файлов проверяются до восстановления. Новые файлы, которых до публикации не было, удаляются только по списку этого выпуска. Остальные страницы сайта не затрагиваются.

Резервные копии автоматически не удаляются. Не удаляйте серверный каталог выпуска до принятия результата. Ручной откат предназначен для последнего выпуска: возврат более старого поверх последующих обновлений требует отдельной проверки.

## 6. Если возникла ошибка

| Сообщение / симптом | Действие |
|---|---|
| `Connection timed out` | Проверить AnyConnect и `Test-NetConnection`. |
| `Permission denied (publickey)` | Проверить SSH-ключ пользователя `stp`; пароль скрипт не запрашивает. |
| `Wrong host` | Остановиться и проверить адрес сервера. |
| `Expected six running consumers` | Проверить состояние и Compose-имена контейнеров. Скрипт сам их не переименовывает. |
| `Insufficient space` | Освободить согласованное место, не удаляя единственную резервную копию. |
| Ошибка SHA256 | Не продолжать с повреждённым пакетом или резервной копией. |
| SSH оборвался во время замены | Не запускать выкладку повторно вслепую. Проверить состояние контейнеров и `result.json`; при необходимости выполнить ручной откат из сохранённого каталога. |
| Ошибка отката | Сохранить весь вывод и каталог выпуска. Если восстановление файлов не удалось, скрипт не запускает потребителей поверх частично восстановленных данных. |

Полезная команда для диагностики:

```powershell
ssh stp@172.17.0.146 "docker ps -a --format 'table {{.Names}}\t{{.Status}}'"
```
