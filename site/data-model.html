Модель данных

Все сырые данные из разных источников (Китай, Турция, Индия, UN Comtrade и т.д.) преобразуются в единую стандартизированную схему и хранятся в одной базе (DuckDB). Ниже - полное описание этой модели.

Таблица unified_trade_data

Основная факт-таблица. Каждая строка - торговый поток за месяц по конкретной стране-партнёру и коду ТН ВЭД.

Поле Тип Описание Пример
NAPR VARCHAR Направление потока относительно РФ: ИМ (импорт) или ЭК (экспорт) ИМ
PERIOD DATE Отчётный период - первый день месяца, формат YYYY-MM-DD 2023-01-01
STRANA VARCHAR Страна-партнёр, двухбуквенный ISO-код CN
TNVED VARCHAR Полный код ТН ВЭД строкой. Ведущие нули сохраняются; короткие коды дополняются справа до 10 знаков 0101210000
EDIZM VARCHAR Дополнительная единица измерения для KOL, как в источнике. ? - неизвестна Number of item
EDIZM_ISO VARCHAR Код стандартизированной единицы (справочник metadata/edizm.csv) 166
STOIM DECIMAL Стоимость в долларах США (в единицах, не в тысячах) 12500500
NETTO DECIMAL Вес нетто, кг 450.0
KOL DECIMAL Количество в единице EDIZM 150
TNVED8 VARCHAR Первые 8 знаков TNVED (подкатегория) 01012100
TNVED6 VARCHAR Первые 6 знаков (субпозиция) 010121
TNVED4 VARCHAR Первые 4 знака (позиция) 0101
TNVED2 VARCHAR Первые 2 знака (группа) 01
SOURCE VARCHAR Источник ряда: national, comtrade или nowcast national
TYPE VARCHAR Тип ряда: fact (факт) или pred (nowcast-прогноз) fact
Уведомление

В Python-пайплайне PERIOD хранится как datetime64[ns] (с нормализацией времени 00:00:00), а при записи в DuckDB приводится к типу DATE.

Состав базы db/unified_trade_data.duckdb

Помимо основной таблицы база содержит справочники и обогащённые представления.

tnved_reference - справочник ТН ВЭД:

  • TNVED_CODE - код;
  • TNVED_LEVEL - уровень (2/4/6/8/10);
  • TNVED_NAME - наименование (без приклеенной единицы измерения);
  • TNVED_NAME_EN - оригинал на английском, из которого сделан машинный перевод (только для NAME_SOURCE IN ('mt','manual'));
  • TNVED_UNIT - дополнительная единица измерения (ШТ, М2, КГ P2O5, …), NULL если не задана;
  • NAME_SOURCE - откуда наименование: fts (справочник ФТС, заморожен 09.02.2022), fns (классификатор ТН ВЭД ФНС, обновляемый), mt (машинный перевод из зарубежного источника), manual (выверено вручную);
  • TRANSLATED - то же, что NAME_SOURCE = 'mt' (оставлено для совместимости).

country_reference - справочник стран: STRANA (ISO2), STRANA_NAME.

hs4_reference - короткие подписи товарных групп: TNVED4, TNVED4_NAME_SHORT (для графиков), TNVED4_NAME_FULL (полное русское название).

unified_trade_data_enriched (view) - join основной таблицы со справочниками плюс вычисляемый period_rank. Кроме TNVED_NAME отдаёт:

  • TNVED_NAME_OFFICIAL - ближайшее наименование из официального справочника: если на 10 знаках лежит машинный перевод, берётся официальный текст на 8, 6, 4 или 2 знаках. Менее подробно, зато проверяемо (99,7 % машинных строк получают официальную подпись на уровне 6 или глубже);
  • TNVED_NAME_OFFICIAL_LEVEL - на каком уровне оно нашлось (NULL, если официального наименования нет ни на одном уровне);
  • TNVED_NAME_EN, TNVED_UNIT, TNVED_NAME_SOURCE - оригинал, единица измерения и происхождение;
  • TNVED_TRANSLATED - то же, что TNVED_NAME_SOURCE = 'mt'.

Индексы физических объёмов (fizob)

  • fizob_index - базовая таблица: STRANA, NAPR, PERIOD, tn_level, tn_code, fizob, fizob_bp.
  • fizob_index_v (view) - надстройка с вычисляемой колонкой idx = fizob / fizob_bp.
  • fizob_enriched - обогащённый индекс, который читают дашборды Superset и API (/v1/fizob, OData fizob): fizob_index_v плюс названия и коды-префиксы, перекластеризованный по STRANA, NAPR, tn_level, tn_code, PERIOD. Индекс считается только по факту (TYPE='fact').

Столбцы fizob_enriched:

Колонка Тип Описание Пример
STRANA VARCHAR страна-партнёр, ISO2 CN
COUNTRY_NAME VARCHAR название страны КИТАЙ
NAPR VARCHAR направление: ИМ / ЭК ИМ
PERIOD DATE отчётный месяц (первое число) 2024-01-01
YEAR INTEGER год, производный от PERIOD 2024
tn_level INTEGER уровень агрегации: 0 (итог по стране), 2 / 4 / 6 (по коду ТН ВЭД) 4
tn_code VARCHAR код ТН ВЭД на уровне tn_level; на уровне 0 равен 0 0101
fizob DOUBLE физический объём текущего периода (рабочая величина) 1.12
fizob_bp DOUBLE физический объём базового периода (знаменатель индекса) 0.0625
idx DOUBLE индекс физического объёма = fizob / fizob_bp, очищенный от изменения цен 0.98
TNVED2, TNVED4, TNVED6 VARCHAR коды-префиксы для join/фильтра 01
TNVED2_NAME, TNVED4_NAME VARCHAR названия группы/позиции (на уровнях 2 / 4) ЖИВЫЕ ЖИВОТНЫЕ
Совет

Строки существуют на каждом уровне отдельно (tn_level 0/2/4/6): при анализе сначала фиксируют один уровень, иначе агрегаты разных уровней смешиваются. Для содержательного показателя берут idx; fizob/fizob_bp - промежуточные величины.

Ключевые концепции и преобразования

  • Гармонизация. Сырые данные в разных форматах приводятся к единой структуре, что позволяет вести унифицированный анализ по странам и периодам.
  • Нормализация ТН ВЭД. Коды хранятся строками, ведущие нули значимы (группы 01-10). Короткие коды дополняются нулями справа до 10 знаков; TNVED2/4/6/8 формируются как префиксы.
  • Нормализация периода. Любые обозначения даты из источников (202301, Jan-2023) приводятся к первому дню месяца (2023-01-01).
  • Направление потока. Значение NAPR определяется относительно России: экспорт из Китая в Россию для нас - импорт (ИМ). Для национальных данных направление инвертируется: Export → ИМ, Import → ЭК.
  • Стандартизация единиц. Оригинальные единицы из EDIZM сопоставляются со справочником (metadata/edizm.csv) и дают код EDIZM_ISO.
  • Происхождение и тип рядов. SOURCE фиксирует источник (national / comtrade / nowcast), TYPE разделяет факт (fact) и прогноз (pred).
  • Nowcast только в «дырах». При финальном merge строки nowcast (TYPE='pred', SOURCE='nowcast') отбрасываются, если для той же торговой ячейки уже есть фактическая строка. Ключ совпадения: PERIOD, STRANA, TNVED (нормализованный к 10 знакам), NAPR. Единица измерения в ключ не входит: наличие факта блокирует nowcast целиком по этой ячейке.
  • Физобъёмы только по факту. Индексы считаются из unified_trade_data только по строкам TYPE='fact', чтобы не смешивать факт с прогнозом.
  • SQL quality gate. После merge выполняются проверки: обязательные таблицы и колонки, валидные значения NAPR / SOURCE / TYPE, отсутствие NULL в PERIOD и отсутствие пересечения pred с фактом по торговому ключу.
