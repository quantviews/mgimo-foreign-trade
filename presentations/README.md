# Презентации проекта

Reveal.js-слайды на Quarto. Общий формат и фирменный стиль МГИМО задаются в
`_quarto.yml`, `slides.css` и `styles/mgimo-reveal.scss`.

| Файл | Что это | Аудитория |
|------|---------|-----------|
| `project-overview.qmd` | Обзор проекта: проблема, архитектура, сравнение с TradeMap и Comtrade, аналитика | заказчик, внешняя презентация |
| `dataviz-story.qmd` | Занятие «Визуализация данных и бизнес-аналитика: как из таблицы сделать понятную историю» (80 мин) | магистранты, Цифровая кафедра |

## Сборка

```bash
quarto render presentations/project-overview.qmd
quarto render presentations/dataviz-story.qmd
```

Один HTML-файл со всеми ресурсами (для передачи заказчику). Профиль `dist`
дополнительно переименовывает файл и встраивает интерактивные графики бюллетеня
и потому привязан к `project-overview`; универсальный профиль — `standalone`:

```bash
quarto run presentations/scripts/export_bulletin_charts.R
quarto render presentations/project-overview.qmd --profile dist
quarto render presentations/dataviz-story.qmd --profile standalone
```

## Занятие по визуализации (`dataviz-story.qmd`)

Сквозная линия — пять шагов от таблицы к графику: **вопрос → срез → метрика →
форма → смысл**. Каждый шаг разбирается на паре «хуже / лучше», построенной на
одних и тех же данных проекта и в одних и тех же осях: отличается только
оформление. Это принципиально, иначе сравнение нечестное.

Занятие рассчитано на аудиторию без ноутбуков, поэтому вместо практикума —
разбор трёх примеров «запрос — результат» в конце. Значения в таблицах
результатов вписаны в разметку: если база пересобрана, их нужно обновить
(запросы приведены на самих слайдах).

На втором слайде и на финальном стоит QR со ссылкой на лендинг проекта.
Картинка — `figures/dataviz/qr-landing.svg`, пересоздаётся так:

```bash
python -m pip install segno
python -c "import segno; segno.make('https://quantviews.github.io/mgimo-foreign-trade/', error='m').save('presentations/figures/dataviz/qr-landing.svg', scale=10, border=3, dark='#003d7a', light=None, omitsize=True)"
```

Второй блок — особенности сбора торговой статистики и их след в цифрах. Он
собран из документации проекта и из разборов конкретных инцидентов:

| Слайд | Источник в репозитории |
|-------|------------------------|
| Капча на портале КНР, проверка валюты выгрузки | `docs/china-collector-docs.md` |
| CSRF-токен и три отдельных запроса MEIDB | `docs/india-collector-docs.md` |
| HTML-страницы и формат чисел `1.234,56` | `docs/turkey-collector-docs.md` |
| «Скелет» таблицы за неопубликованный месяц | `docs/india-collector-docs.md`, шаг 8 |
| Молчаливая обрезка ответа по `maxRecords` | `docs/comtrade-collector-docs.md`, разд. 7 |
| Пересмотры отчётности и манифест | `docs/comtrade-collector-docs.md`, разд. 5 |
| `CH` вместо `CN` и задвоение Китая | `docs/china-country-code-fix.md` |

Если цифры в этих слайдах меняются (например, после пересборки Comtrade),
поправьте их в разметке: они вписаны в HTML вручную, а не считаются при рендере.

### Слайды про дашборд

Состав дашборда взят из экспорта в `superset/dashboards/*.zip`: названия вкладок
и чартов, набор фильтров и датасет `unified_trade_data_enriched`. Если дашборд
переделан, экспортируйте его заново и сверьте два слайда — «Дашборд проекта»
и «Фильтры: срез делает читатель».

Картинка `figures/dataviz/superset-filters.png` — обрезанный снимок панели
фильтров с живого инстанса. Адрес инстанса и учётные данные на слайдах
намеренно не указаны: презентация публикуется, а репозиторий открытый.

### Графики

Строятся при рендере из `site/data/*.parquet`, функции — в
`scripts/dataviz_helpers.R`.

| Кейс | Данные | Вывод |
|------|--------|-------|
| Спагетти из 98 групп ТН ВЭД | `figures/dataviz/spaghetti_cn_import.parquet` | серый фон вместо удаления рядов |
| Доллары против тонн | `bulletin_headline.parquet` | метрика меняет вывод на противоположный |
| Пирог против столбцов | `df_groups.parquet` + `hs4_labels.parquet` | длина сравнивается точнее угла |
| Агрегат прячет историю | `tab_stoim_oil.parquet` | итог тот же, состав торговли другой |
| Обрезанная ось | `bulletin_headline.parquet` | столбцам нужен ноль |
| Заголовок-вывод | `bulletin_fo.parquet` | тот же график, другой заголовок |
| Наукаст | `bulletin_headline.parquet` | прогноз рисуется иначе, чем факт |
| Запрос → график | `figures/dataviz/example_cn_export.parquet` | график строится по результату показанного SQL |

Графики выводятся с прозрачным фоном (`dev.args = list(bg = "transparent")`),
иначе svglite подкладывает белый прямоугольник и график выглядит вклеенным.

### Кэши

Два среза лежат вне git — `data_processed/fizob_2.parquet` (13 МБ) и
`db/unified_trade_data.duckdb` (1,5 ГБ). Чтобы презентация собиралась без
полного пайплайна, оба закэшированы рядом с ней:

| Файл | Размер | Что внутри |
|------|--------|------------|
| `figures/dataviz/spaghetti_cn_import.parquet` | 53 КБ | 98 групп ТН ВЭД, импорт из Китая, с 2022 года |
| `figures/dataviz/example_cn_export.parquet` | 2 КБ | результат SQL-запроса со слайда «От запроса к графику» |

Второй кэш существует именно для честности слайда: на нём показан запрос, и
график строится ровно по тем строкам, которые этот запрос вернул. Пересобрать
оба:

```bash
cd presentations && Rscript scripts/dataviz_cache.R
```

Если `data_processed/fizob_2.parquet` на месте, «спагетти» берётся из него, а
кэш не используется. Пример пересобирается только при наличии базы DuckDB.

### Оформление

`dataviz.css` сознательно обходится без карточек, рамок, заливок и теней:
иерархия задаётся типографикой, воздухом и тонкими линейками. Компоненты —
`.lead`, `.note`, `.concl`, `.cols-2` / `.cols-3`, `.facts`, `.steps`,
`ol.numbered`, `ol.hang`, `.pair`, `table.plain`, `table.raw`. Файл
подключается только к этой презентации и не затрагивает `project-overview`.

### Две ловушки вёрстки

**Pandoc заворачивает многострочный HTML внутри `<div>` в `<p>`.** Для
grid-контейнера это значит, что дочерние элементы перестают быть
grid-элементами и раскладка рассыпается. Лечится `display: contents` на обёртке
либо записью блока в одну строку без пустых строк внутри.

**Заголовок внутри fenced-div превращает его в `<section>`.** Если написать
`#### Название` внутри `::: {.c}`, Quarto отдаст `<section class="c">`, и
селекторы вида `.cols-3 > div` перестанут срабатывать. Поэтому подзаголовки
колонок размечены как `[Название]{.ch}`.

### Проверка раскладки

Слайды плотные, и текст легко выходит за границы. Перед показом полезно
измерить переполнение в браузере, а не искать его глазами: для каждой секции
`.reveal .slides > section` сравнить `scrollHeight` с `clientHeight`, а правую
границу каждого потомка — с правой границей слайда.

Скриншотить reveal в headless Chrome не стоит: масштабирующая трансформация
`.slides` не попадает в снимок, а кадр отстаёт на слайд. Для визуальной
проверки надёжнее развернуть колоду в статичные кадры 1280×720
(`position: static`, `transform: none`) и показывать по одной секции.
