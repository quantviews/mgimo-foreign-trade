# MGIMO trade - MCP-сервер

[MCP](https://modelcontextprotocol.io)-сервер, который отдаёт API внешней
торговли МГИМО (`https://nts.mgimo.ru/api`) в виде инструментов, чтобы любой
MCP-клиент (Claude Desktop, IDE, агенты) мог отвечать на вопросы по данным
обычным языком. Это тонкая обёртка над HTTP API: авторизация, квоты и аудит
остаются на стороне API.

Работает в двух режимах: **локально (stdio)** - клиент сам запускает сервер, ключ
в переменной окружения; и **удалённо (streamable-http)** - хостится на VPS, ключ
идёт в заголовке каждого запроса.

## Сравнение с выгрузкой в Excel

Напишите обычным языком:

> Сравни экспорт нефти в Индию и Китай за последние 12 месяцев и дай выгрузку в Excel.

В ответе будут стоимость, масса и динамика индекса физического объема (fizob), а также Excel-файл. Стоимость и масса сравниваются за одинаковые месяцы факта внутри запрошенного окна. Если общий факт есть только за 11 из 12 месяцев, ответ явно назовет исключенный месяц, а не выдаст неполный период за полный.

В Excel три листа:

- **«Данные»**: выбранный помесячный ряд, включая оценки, если они запрошены.
- **«Сравнение»**: те же общие месяцы, суммы, разницы и проценты, что и в ответе.
- **«Описание»**: источники, единицы, фильтры, исключенные месяцы и методология.

Fizob показывает изменение сглаженного индекса между первым и последним общим месяцем; для каждой страны начало = 100. Это не рост суммы тоннажа за период. Индекс доступен для странового итога или одного товарного кода уровня 2/4/6. Агрегация разных физических единиц - особенность методологии проекта. Если сопоставимого индекса нет, причина будет указана, фильтры не расширяются.

Один файл ограничен 1 000 строками, 60 месяцами и 5 МБ (по тарифу лимит может быть ниже). За последние 24 часа на пользователя: до 10 новых файлов, суммарно 5 000 строк и 20 МБ. Лимит общий для чата, API и MCP. Файл доступен 7 дней; повторное скачивание не расходует квоту выгрузок.


## Инструменты

| Инструмент | Что делает |
|---|---|
| `resolve_trade_route` | проверяет маршрут относительно России по исходному вопросу |
| `search_products` | поиск кандидатов по свободному описанию в русском справочнике ТН ВЭД; уровни 2/4/6 |
| `product_overview` | обзор товарной группы: название, партнеры, доли и сопоставимая динамика с проверяемыми числами |
| `verify_trade_answer` | проверяет ссылки на рассчитанные суммы, динамику и экстремумы; возвращает готовый ответ |
| `rank_trade` | рейтинг групп ТН ВЭД-2 по стоимости, доли от всех групп и покрытие по месяцам |
| `explain_trade` | динамика год к году, доли и вклады подкатегорий |
| `compare_trade` | сравнение стран за общие месяцы факта: стоимость, масса и fizob |
| `export_trade` | создание XLSX по выбранным фильтрам |
| `download_export` | скачивание созданного XLSX с авторизацией |
| `meta` | последний доступный период + ваш тариф и остаток квоты |
| `reference` | справочники кодов: `countries` (ISO-2 + русские названия) или `tnved` (названия кодов ТН ВЭД, по `level`) |
| `trade` | строки торговли или агрегаты на сервере (фильтры: страна, направление, код ТН ВЭД, период, `group_by`, `metrics`) |
| `fizob` | индексы физобъёмов (реальные объёмы без влияния цен - особенность проекта) |

## Требования

- Python 3.10+.
- Персональный API-ключ. Получить в кабинете Superset:
  <https://nts.mgimo.ru/superset/apikey/> (нужна роль `API`, назначает админ).

## Установка

Через [uv](https://docs.astral.sh/uv/) (рекомендуется, без ручного venv):

```bash
cd mcp-server
uv sync
```

Или обычный pip в виртуальном окружении:

```bash
cd mcp-server
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Подключение MCP-клиента (локально, stdio)

Клиент запускает `server.py`, ключ передаётся в `env`. Токен уходит только в
заголовок Authorization и нигде не печатается.

**Claude Desktop** - откройте `claude_desktop_config.json`
(macOS: `~/Library/Application Support/Claude/`, Windows: `%APPDATA%\Claude\`),
добавьте сервер и перезапустите Claude Desktop:

```json
{
  "mcpServers": {
    "mgimo-trade": {
      "command": "uv",
      "args": ["run", "--directory", "/АБСОЛЮТНЫЙ/ПУТЬ/К/mcp-server", "mgimo-trade-mcp"],
      "env": { "MGIMO_API_TOKEN": "mgt_ВАШ_ТОКЕН" }
    }
  }
}
```

Без uv - запускайте скрипт напрямую тем Python, где установлены зависимости:

```json
{
  "mcpServers": {
    "mgimo-trade": {
      "command": "/АБСОЛЮТНЫЙ/ПУТЬ/К/mcp-server/.venv/bin/python",
      "args": ["/АБСОЛЮТНЫЙ/ПУТЬ/К/mcp-server/server.py"],
      "env": { "MGIMO_API_TOKEN": "mgt_ВАШ_ТОКЕН" }
    }
  }
}
```

На Windows укажите полный путь к `python.exe` и слэши в путях, например
`C:\\...\\.venv\\Scripts\\python.exe`.

Другие MCP-клиенты (Cursor, Continue и т.п.) настраиваются так же: stdio-сервер,
запускаемый этой командой, и `MGIMO_API_TOKEN` в окружении.

## Удалённый (хостинг) сервер

На VPS работает готовый экземпляр по адресу **`https://nts.mgimo.ru/mcp`**
(транспорт Streamable HTTP, TLS). Ставить ничего не нужно: каждый запрос должен
нести персональный ключ клиента в `Authorization: Bearer <ключ>`, который сервер
прокидывает в API. Поэтому квоты и аудит считаются по каждому пользователю, а сам
сервер токен не хранит.

### Подключение ИИ-клиентов (удалённо)

Всем клиентам нужно одно и то же: транспорт **streamable-http**, URL
**`https://nts.mgimo.ru/mcp`** и ваш ключ в заголовке **`Authorization: Bearer`**.
Сначала получите ключ в кабинете Superset:
<https://nts.mgimo.ru/superset/apikey/>. После подключения клиент увидит
инструменты `meta`, `reference`, `trade`, `fizob`.

**Claude Desktop** - для удалённых серверов он ждёт OAuth, поэтому bearer-ключ
проще подключить через мост [`mcp-remote`](https://www.npmjs.com/package/mcp-remote)
(нужен Node.js). Откройте `claude_desktop_config.json` (Windows `%APPDATA%\Claude\`,
macOS `~/Library/Application Support/Claude/`) и перезапустите:

```json
{
  "mcpServers": {
    "mgimo-trade": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://nts.mgimo.ru/mcp",
               "--header", "Authorization: Bearer mgt_ВАШ_ТОКЕН"]
    }
  }
}
```

**Claude Code (CLI)** - умеет удалённый HTTP MCP с заголовком напрямую:

```bash
claude mcp add --transport http mgimo-trade https://nts.mgimo.ru/mcp \
  --header "Authorization: Bearer mgt_ВАШ_ТОКЕН"
```

**Cursor** - надёжнее всего через мост
[`mcp-remote`](https://www.npmjs.com/package/mcp-remote) (нужен Node.js): он сам
держит соединение с заголовком и отдаёт его Cursor как stdio, минуя нативную
логику Cursor, которая с OAuth-сервером ведёт себя нестабильно (пробует OAuth и
теряет статический заголовок → 401). В `.cursor/mcp.json` (в корне проекта) или
`~/.cursor/mcp.json` (глобально):

```json
{
  "mcpServers": {
    "mgimo-trade": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://nts.mgimo.ru/mcp",
               "--header", "Authorization: Bearer mgt_ВАШ_ТОКЕН"]
    }
  }
}
```

Без Node - чистый OAuth: оставьте только `url` (без `headers`), Cursor откроет
браузер с нашей страницей входа для ключа:

```json
{ "mcpServers": { "mgimo-trade": { "url": "https://nts.mgimo.ru/mcp" } } }
```

Настроить можно и через интерфейс: **Settings → MCP** (в новых версиях **Tools &
Integrations**) → **New MCP Server** → тот же JSON. После подключения сервер
`mgimo-trade` загорится зелёным и покажет инструменты `meta`, `reference`,
`trade`, `fizob`; пользоваться в чате в режиме **Agent**. Токен в `.cursor/mcp.json`
хранится в открытом виде - файл в проекте лучше не коммитить.

> Нативный `url` + `headers` со статическим ключом у Cursor может давать 401 с
> нашим OAuth-сервером - используйте `mcp-remote` или чистый OAuth выше.

**VS Code** (Copilot, режим Agent) - формат отличается: файл `.vscode/mcp.json`,
ключ `servers` и `type: http`:

```json
{
  "servers": {
    "mgimo-trade": {
      "type": "http",
      "url": "https://nts.mgimo.ru/mcp",
      "headers": { "Authorization": "Bearer mgt_ВАШ_ТОКЕН" }
    }
  }
}
```

**Свой агент (Python)** - или любой MCP-совместимый фреймворк (адаптеры
LangChain / LlamaIndex, собственный цикл):

```python
from mcp import ClientSession
from mcp.client.streamable_http import streamablehttp_client

async with streamablehttp_client(
        "https://nts.mgimo.ru/mcp",
        headers={"Authorization": "Bearer mgt_ВАШ_ТОКЕН"}) as (r, w, _):
    async with ClientSession(r, w) as s:
        await s.initialize()
        print([t.name for t in (await s.list_tools()).tools])
        print((await s.call_tool("meta", {})).content[0].text)
```

**Claude (веб и мобильное приложение) и ChatGPT** - через OAuth. Сервер
поддерживает OAuth 2.1, поэтому эти клиенты подключаются как «удалённый коннектор
по URL» - без файлов конфигурации и без Node.js:

1. В настройках клиента добавьте коннектор / MCP-сервер по URL
   `https://nts.mgimo.ru/mcp` (в Claude: **Settings → Connectors → Add custom
   connector**; в ChatGPT: **Settings → Connectors**, на платном тарифе /
   Developer Mode).
2. Клиент проведёт OAuth-вход: откроется наша страница, вставьте персональный
   ключ (`mgt_...` из кабинета) - готово.

Коннектор синхронизируется на все устройства, включая **телефон** (Claude на
мобиле). Ключ вводится один раз, на сервере в открытом виде не хранится
(access-token привязывается к ключу).

**GigaChat, YandexGPT и другие модели без нативного MCP** - коннектора «по URL» у
них нет, но подключаются кодом через function calling. Соберите свой агент: модель
как LLM, а инструменты `meta`, `reference`, `trade`, `fizob` берите из нашего MCP
(через MCP-клиент, см. пример на Python выше) или напрямую из REST API
`https://nts.mgimo.ru/api`. Ключ при этом остаётся вашим (учёт per-user).

Хотите запускать у себя, а не через хостинг? Используйте локальный stdio-режим
выше (["Подключение MCP-клиента"](#подключение-mcp-клиента-локально-stdio)) с
`MGIMO_API_TOKEN` в окружении.

### Деплой / обновление хостинг-сервера (VPS)

Сервер работает контейнером `trade-mcp` рядом с `trade-api`, в Docker-сети
Superset, за nginx контейнера `landing` на `/mcp` (см. `deploy/landing-nginx.conf`).
API он зовёт внутренне (`trade-api:8000`) и токен не хранит.

```bash
ssh mgimo
cd ~/mgimo-foreign-trade && git pull
cd mcp-server
set -a; . ../api/.env; set +a     # берём MGIMO_API_POSTGRES_DSN (OAuth-клиенты в Postgres)
docker compose up -d --build      # собрать + (пере)запустить trade-mcp
```

Локация `/mcp` в nginx уже есть; после её правки:
`scp deploy/landing-nginx.conf mgimo:/home/marcel/landing-nginx.conf && \
 ssh mgimo "docker exec landing nginx -t && docker exec landing nginx -s reload"`.

Проверка: `curl -sN -H "Authorization: Bearer mgt_..." https://nts.mgimo.ru/mcp`
должен говорить на MCP (голый GET отдаёт 406/JSON - это нормально; вызывать
инструменты нужно настоящим клиентом).

**OAuth.** Для http-транспортов включён OAuth (`MCP_OAUTH=1`): FastMCP монтирует
`/.well-known/oauth-*`, `/register`, `/authorize`, `/token`, `/revoke` в корне
домена (nginx проксирует эти пути на `trade-mcp` отдельной regex-локацией), а
страница ввода ключа - `/oauth/login`. Токены **stateless**: access/refresh - это
сам API-ключ, на сервере он не хранится (как и у клиентов с заголовком; API держит
только `sha256`). Поэтому вызовы переживают перезапуск контейнера **без повторного
входа**. Регистрации OAuth-клиентов (не секрет) персистятся в Postgres
(`api.mcp_oauth_clients` в БД `tradeapi`, DSN из `MGIMO_API_POSTGRES_DSN`), чтобы и
refresh переживал рестарт; коды авторизации короткоживущие и лежат в памяти. Без
DSN клиенты хранятся в памяти (тогда refresh после рестарта попросит вход заново).

## Переменные окружения

| Переменная | По умолчанию | Примечание |
|---|---|---|
| `MGIMO_API_TOKEN` | нет | обязательна в stdio-режиме; персональный ключ |
| `MGIMO_API_BASE` | `https://nts.mgimo.ru/api` | переопределение для локального/dev API |
| `MCP_TRANSPORT` | `stdio` | `stdio`, `streamable-http` или `sse` |
| `MCP_HOST` | `127.0.0.1` | адрес привязки для http-транспортов |
| `MCP_PORT` | `8000` | порт для http-транспортов |
| `MCP_OAUTH` | `1` | OAuth-сервер для http-транспортов; `0` - выключить |
| `MCP_ISSUER_URL` | `https://nts.mgimo.ru` | issuer OAuth (корень домена; там же `/authorize`, `/token`, `/register`) |
| `MCP_RESOURCE_URL` | `https://nts.mgimo.ru/mcp` | адрес MCP-ресурса для метаданных |

В stdio-режиме, как запасной вариант, сервер также читает строку
`MGIMO_API_TOKEN=` из `.env` рядом с `server.py` или в рабочем каталоге - удобно
для локальных тестов. Такой `.env` в репозиторий не коммитить.

## Заметки

- Только чтение: инструменты делают лишь GET-запросы к `/v1/*`.
- Тот же ключ работает для OData-фида (Excel/Power BI) и для skill trade-data.
- Справочник: [`docs/api-reference.md`](../docs/api-reference.md).
- **Держать в паре со скиллом.** Описания инструментов и правила здесь
  (`server.py`: докстроки `trade/fizob/...` и `INSTRUCTIONS`) - это отдельная копия
  того же, что в [`.claude/skills/trade-data/SKILL.md`](../.claude/skills/trade-data/SKILL.md).
  При изменении API (новый параметр, эндпоинт, правило) правьте оба места, иначе
  MCP и скилл разойдутся.


## Полные выгрузки для широких вопросов

- `export_trade`: общий API формирует помесячный XLSX и краткую сводку. Передайте
  страны, товарные коды и начальный период. По умолчанию конечный месяц актуален
  на момент запроса. `end_mode="fixed"` нужен только для заданной конечной даты.
- `download_export(export_id)`: получает XLSX в JSON (`encoding=base64`, `content`, `filename`, `mime_type`) с авторизацией текущего
  пользователя. Агент может сохранить его в файл/артефакт, если клиент это умеет.
  Не следует вставлять сотни строк XLSX в чат или обещать созданное вложение,
  если клиент не поддерживает файлы.

Ссылка `download_url` требует заголовка Authorization. Это не публичная ссылка
для браузера; ключ в ней отсутствует. Для агентов предпочтителен инструмент
`download_export`, который сам передаст токен. Максимум 1 000 строк, дополнительно
ограничено тарифом API, и 5 МБ. Файл доступен владельцу 7 дней. Неполная выдача
отклоняется, а не выдаётся за полный результат. Лимиты API учитывают создание
и скачивание. Внешние агенты и демо-чат используют один механизм подготовки XLSX.

Обязательны `period_from` и выбор стран либо товарной группы. Максимум 60 месяцев включительно; неверные фильтры возвращают 400. Файл не обрезается автоматически.
Миграция `010_xlsx_exports.sql` добавляет бинарное хранение XLSX. Старые CSV доступны до истечения своих ссылок.
Дополнительно действует общая квота XLSX-выгрузок на аккаунт: 5 000 строк, 20 МБ (20 000 000 байт) и 10 файлов за скользящие 24 часа. API, MCP и демо суммируются; все токены одного пользователя расходуют общую квоту. Повторное скачивание существующего файла не учитывается повторно. Создание нового файла с теми же фильтрами учитывается. При превышении - 429 с Retry-After; частичный файл не создается. Квота хранится в Postgres и не сбрасывается при рестарте. Ошибка сохранения откатывает списание. Учет начинается с установки миграции 011; ранее созданные файлы задним числом не списываются.
Клиент декодирует `content` из base64 в бинарный файл; не вставляет base64 в чат.

Миграция `011_export_quota.sql`: таблицы `api.export_usage`, `api.export_delegates`, функция `api.reserve_export`. Делегирование `X-Export-User-Id` разрешено только явно зарегистрированному токену демо-сервиса; ID берется из проверенной сессии, не из аргументов модели. При замене сервисного токена требуется обновить `export_delegates`.
Ограничение относится к `/v1/exports/trade`. Обычные REST/OData-ответы регулируются своими тарифными лимитами; суммарный объем этих ответов данная квота не ограничивает.

### Правила сравнения и оформления

MCP и обе копии trade-data (`.agents/skills/trade-data/SKILL.md`, `.claude/skills/trade-data/SKILL.md`) используют одинаковую памятку: сравнивать общие месяцы факта внутри заданного интервала, явно указывать сокращение периода, отделять прогнозы, показывать абсолютную разницу и базу процентов. Нулевые прогнозные строки не расширяют период оценки. Годовые сравнения требуют одинаковых календарных месяцев.
Ответ начинается с сути; страны названы словами, числа имеют разделители разрядов и десятичную запятую. Итоги `export_trade.summary` сами по себе не гарантируют сопоставимых периодов. Это инструкции внешнему агенту, а не принудительный пересчет ответа MCP-сервером. После обновления переподключите MCP, чтобы клиент получил новые инструкции.

### Сравнение стран одним инструментом

`compare_trade(strana=["IN", "CN"], napr="ex", tnved4=["2709"], months=12)` - первый инструмент для сравнения стран. Сам читает последний период базы, выбирает пересечение месяцев факта, возвращает общие и исключенные месяцы, суммы и разницы. Проценты рассчитаны относительно первой страны в `strana`; при неположительной базе процент не рассчитывается. Неполный ответ API отклоняется. До 10 стран и 60 месяцев; вызов общего API сравнения учитывается обычными квотами.
`answer_ru` содержит готовую сводку с округлением для отображения; точные десятичные значения сохранены строками в `totals` и `differences`. Файл не создается, квота XLSX не расходуется. Для явного интервала задайте `period_from` и `period_to`. Это сравнение стран, не отдельный инструмент динамики год к году.

### Fizob в compare_trade

По умолчанию `include_fizob=true`: для странового итога (уровень 0) либо одного кода HS2/4/6 добавляется `physical_volume`. Произвольные корзины кодов и полный TNVED не заменяются более широким агрегатом; инструмент возвращает объяснение недоступности блока. `include_fizob=false` отключает его.

Метод проверен по `src/fizob_queries.R` и `src/pipelines/merge_pipeline.py`: исходная выборка только fact; месячная сетка заполняется нулями, часть количеств восстанавливается через цену; используются 12-месячные скользящие средние. Товарные уровни имеют текущие стоимостные веса. Агрегация товаров с разными физическими единицами в страновом итоге является осознанной особенностью методологии fizob и позволяет анализировать динамику разнородной товарной корзины. Разные единицы сами по себе не являются основанием объявлять индекс ошибочным или несопоставимым. R уже нормирует fizob, а serving-слой дополнительно вычисляет `idx=fizob/fizob_bp`; абсолютный уровень idx не интерпретируем как общий процент от единой базы.

Сравниваем изменение между первым и последним общими месяцами факта: `(idx_end / idx_start - 1) * 100`. Это динамика сглаженного индекса между точками, не рост суммарных объемов за интервал и не обязательно годовой темп. Каждая страна показана на собственной шкале «начало=100»; разница динамики стран выражена в процентных пунктах. Индексы по месяцам/товарам/странам не складываются и не усредняются.

Перед расчетом проверяются точный агрегат, направление, уникальность строк, наличие индексов во всех общих месяцах, конечность и неотрицательность значений, положительное начало и постоянство `fizob_bp` (относительный допуск 1e-9). Пропуск индекса не меняет молча период: блок fizob недоступен, стоимостное сравнение остается. Пределы конечных точек задаются наличием факта в trade, поскольку сама сетка fizob может содержать заполненные месяцы без публикаций.


### Сравнение в Excel-выгрузке

XLSX содержит листы «Данные», «Сравнение» и «Описание». При выборе 2-10 стран, одного направления и мер `stoim,netto` сравнение использует только общие месяцы факта внутри заданного окна. На листе показаны стоимость, масса, разницы и проценты относительно первой выбранной страны. Исходный помесячный ряд, включая запрошенные оценки, остается на листе «Данные».

fizob добавляется для странового итога или одного кода уровня 2/4/6. Каждая страна приведена к собственной начальной точке = 100; динамика считается между крайними общими месяцами. Это сглаженный индекс, а не рост суммы тоннажа за период. Агрегация разных физических единиц - особенность методологии проекта. При недостатке индексов или дополнительных фильтрах по источнику/единице причина отсутствия fizob указана явно, фильтры не расширяются.

Лист «Описание» содержит источники, единицы, фильтры, общие и исключенные месяцы и формулы. Ограничения файлов и суточные квоты сохранены: производные строки сравнения не расширяют исходный срез, размер всего XLSX учитывается в квоте. Старые файлы не меняются, для нового листа нужно создать новую выгрузку. Расчет общий с MCP `compare_trade` через `POST /v1/compare/trade`.

Внешний MCP-клиент вызывает `compare_trade`, затем `export_trade` с тем же запрошенным окном (`end_mode="fixed"`), странами, направлением и товарами; `download_export` получает XLSX. Для итогового ответа используйте `comparison` из результата выгрузки: он рассчитан вместе с файлом. Не сравнивайте общие суммы `summary`, если периоды стран отличаются. Вложение требует поддержки со стороны клиента; не публикуйте API-ключ в ссылке.


### Качество количественных данных

Ответ `trade` и Excel содержат `quality_flags` (в OData: `QUALITY_FLAGS`). Предупреждения сохраняются и в агрегатах. Неизвестная масса возвращается как `null`, в Excel ячейка пустая; ее нельзя трактовать как ноль. Если хотя бы у одной строки выбранного агрегата масса неизвестна, полный итог массы не рассчитывается. Аналогично обрабатываются пропуски дополнительного количества `kol`.

Для Турции отмечаются скрытая товарная детализация и записи 8703 с массой менее 100 кг на транспортное средство. Это диагностический порог, не доказательство ошибки; положительные исходные значения сохранены. Единицы дополнительного количества задают масштаб (например, тысячи штук), их не следует автоматически считать штуками.

По информации команды, Турция не раскрывает статистику сырой нефти. Скрытая позиция `27999999` предположительно связана с ней, но состав позиции не подтвержден. Не следует автоматически относить весь ее объем к 2709 или считать отсутствие открытых данных отсутствием поставок.

### От общего к частному

На вопросы о причинах динамики агент сначала проверяет общий итог и сопоставимость периодов, затем разбирает подкатегории на следующем уровне кодов. Показывает доли сейчас и год назад, абсолютное изменение и вклад в темп роста родительской группы (п.п.). Сумма подкатегорий сверяется с общим итогом; неполный срез не выдается за полное объяснение. Количество сравнивается внутри одинаковых единиц, индексы fizob не складываются.

Пример: «Как изменился импорт легковых автомобилей (8703) из Китая за последние 12 доступных месяцев год к году? Объясни за счет каких подкатегорий: доли и вклад в изменение». Для простой выгрузки дополнительный разбор не запускается.

Расчеты выполняет общий MCP-инструмент `explain_trade(strana="CN", napr="im", code="8703", months=12)`. Он проверяет наличие одинаковых календарных месяцев в обоих годах и сверяет суммы подкатегорий с родительскими итогами. Отсутствующая категория не заменяется нулем: ее часть изменения остается нераспределенной. Разложение относится к стоимости; количество и fizob не выводятся из денежных долей. `explain_trade` возвращает названия из русского справочника базы (`name`, `name_source`, `name_status`); если названия нет, агент сохраняет код и сообщает об отсутствии подписи.

Названия подкатегорий приходят из русского справочника базы вместе с кодами. Агент использует их без повторного перевода. Для гибридных групп 870340, 870350, 870360 и 870370 исправлены шестизначные подписи и укрупненные записи с нулями справа. Английский обход удален. Правки закреплены в metadata/translations/name_overrides.json через exact_level, поэтому следующие сборки их сохраняют; более подробные национальные коды не меняются. Ранее сформированные Excel-файлы остаются прежними, новые получают обновленный справочник.

### Разбор год к году и исходные данные в Excel

Пример для «Спросить ИИ»:

> Как изменился импорт легковых автомобилей (8703) из Китая за последние 12 доступных месяцев год к году? Объясни доли и вклад подкатегорий. Дай исходные данные обоих периодов в Excel, факт и nowcast отдельно.

Чат связывает выгрузку с периодами и источником `explain_trade`. В файле:

- «Факт»: доступные исходные помесячные строки текущего периода и тех же месяцев годом ранее. `comparison_period=current` / `previous` различает окна.
- «Nowcast»: модельные оценки проекта отдельно, без включения в фактические итоги.
- «Описание»: границы периодов, источники, единицы, фильтры и правила интерпретации.

Доли и вклады рассчитаны для ответа, в Excel сохраняются исходные данные для воспроизведения расчетов. В чате допустимы сокращенные названия с точным кодом; Excel сохраняет русские названия из базы.

Если факта за один из месяцев нет, файл сохраняет доступные наблюдения обоих окон, но ответ не рассчитывает полный итог год к году и перечисляет пропуски. Период не сдвигается незаметно. Наличие всех месяцев само по себе не гарантирует полноту товарного покрытия. Неизвестные количество и масса остаются пустыми; сумму известных значений нельзя представлять как полный итог.

`SOURCE=comtrade`, `TYPE=fact` может содержать оценки физических показателей самого источника. Они сохраняются с признаками качества и не относятся к nowcast проекта (`TYPE=pred` или `SOURCE=nowcast`). Выбранная национальная статистика не дополняется Comtrade молча.

Оба периода и все строки nowcast учитываются в лимитах файла и суточной квоте. Старые файлы не меняются; нужно сформировать новую выгрузку.

**Граница возможностей MCP:** `explain_trade` проверяет сопоставимость и возвращает `available=false` с `missing_months`, если нет полного родительского ряда. Он сам не создает Excel. Автоматическая связка разбора и двухпериодной выгрузки реализована в «Спросить ИИ». Параметр `compare_yoy=true` есть в REST `POST /v1/exports/trade`, но пока отсутствует в сигнатуре MCP `export_trade`. Не передавайте его этому инструменту и не обещайте внешнему MCP-клиенту листы «Факт» / «Nowcast» автоматически. Обычный MCP-экспорт сохраняет `type` и `source` в исходных строках; для специального формата используйте чат или REST API.

### Порядок аналитического ответа

Ответ начинается с изменения агрегата и главных драйверов, затем показывает доли и вклад подкатегорий, изменение структуры. Краткая справка об источнике и существенных ограничениях идет после анализа. Ограничение, которое делает основной вывод невозможным, сообщается сразу. Источник называется прямо, например «таможенная статистика Китая»; перечень исключенных источников и внутренние поля API не повторяются без необходимости. Сокращенные названия допустимы с точным кодом, в Excel сохраняется справочник базы. Проверки полноты и разделение факта, оценок источника и nowcast остаются обязательными.


## Топ товарных групп

Для рейтинга групп по стоимости используй MCP `rank_trade` первым: `rank_trade(strana="TR", napr="im", top_n=10)` для импорта из Турции в этом году. Без дат инструмент выбирает январь - последний месяц года из актуальности базы. Для другого периода передай обе даты. Инструмент работает по главам ТН ВЭД-2 и факту, возвращает названия, доли и общий объем по ВСЕМ группам; в `data` только запрошенные лидеры.

`ranking.complete_universe=true` и `shown_groups < total_groups` означают выбранный топ из полного списка, а не усечение. Используй готовые `total_stoim`, `share_pct`, `top_share_pct`, `other_groups_stoim`. Назови фактические месяцы и пропуски из `fact_months` / `missing_months`. Полный знаменатель не гарантирует полноты исходной статистики. Excel для рейтинга не нужен.

Если MCP недоступен, через `query.py trade` получи все агрегаты `tnved2` с `type=fact`, названиями, сортировкой `-stoim` и достаточным limit; проверь `meta.has_more`. Считай знаменатель только по полному списку, затем выбери топ. В обычном `trade` флаги `has_more` / `_truncated` остаются признаком неполного ответа: нельзя просто игнорировать их или считать доли от суммы первых N строк. Проверь месяцы отдельным агрегатом. Не превращай данные за часть года в годовой итог.

### Параметры и результат `rank_trade`

```python
rank_trade(strana="TR", napr="im", top_n=10)
# Явно заданный период:
rank_trade(strana="TR", napr="im", top_n=5,
           period_from="2026-01", period_to="2026-08")
```

| Параметр | Значение |
|---|---|
| `strana` | Одна страна, код ISO2, например `TR` |
| `napr` | Направление относительно России: `im` / `ИМ` или `ex` / `ЭК` |
| `top_n` | От 1 до 40, по умолчанию 10 |
| `period_from`, `period_to` | Месяцы в формате `YYYY-MM` или `YYYY-MM-01`; максимум 60 месяцев. Конечный месяц не позднее актуальности базы |

Если даты отсутствуют, используется январь - последний доступный месяц года базы. Если указан только конец, начало выбирается с января этого года; если только начало, конец соответствует последнему месяцу базы.

В `data` возвращаются лидеры: `tnved2`, `tnved2_name`, `stoim` (доллары США), `share_pct` (проценты от всех групп). В `ranking` находятся общий итог `total_stoim`, остаток `other_groups_stoim`, доля лидеров `top_share_pct`, число всех и показанных групп, запрошенный период, фактические и отсутствующие месяцы, источники. `meta.period_max` сообщает актуальность базы. Денежные итоги в `ranking` передаются десятичными строками.

Инструмент ранжирует только по стоимости и только на уровне ТН ВЭД-2, с `type=fact`. Nowcast не включается. Флаг `complete_universe` подтверждает получение всех агрегатов API, но не полноту публикаций первоисточника. При усечении исходного ответа или расхождении итогов инструмент возвращает ошибку `Ranking unavailable`; публиковать рассчитанные по такому ответу доли нельзя.

### Предупреждения по показателям

Область предупреждений о качестве: связывай каждый флаг только с проверяемым показателем. Предупреждение о массе относится к массе и производным от нее (цена за кг, динамика массы); предупреждение о количестве или единице относится к количеству и производным от него. Низкая масса на транспортное средство сама по себе не доказывает ошибку стоимости. Стоимость, ее динамику и доли по стоимости ставь под сомнение только при отдельном свидетельстве проблемы стоимости или покрытия. Для топа по стоимости не добавляй оговорку о массе, если масса не используется в выводах. Не скрывай соответствующие флаги при ответах о физических показателях. Если предупреждение неоднозначно, не расширяй его смысл на другие показатели.

## Неполные периоды и нулевые строки

Неполные периоды и нулевые строки: различай запрошенное окно, месяцы имеющихся фактических записей и nowcast. Если фактического месяца нет, пиши «Полный фактический итог за запрошенный период не установлен; в доступных записях отражено ...». Не характеризуй масштаб торговли как малый или редкий по неполному срезу. Количество или массу при пропусках называй только известной частью. Нулевая стоимость в существующей строке означает запись со значением 0, а не отсутствие наблюдения; не объясняй ее округлением или отсутствием торговли без подтверждения источника. NULL не равен нулю. Национальный источник и TYPE=fact не доказывают непосредственно наблюдаемую природу физических показателей.
Для Excel одного товара HS2/HS4 и одной страны с аналитическим разбором сначала вызови explain_trade за запрошенное окно (не более 12 месяцев), затем export_trade за тот же период. available=false или missing_months запрещает полный рост год к году, доли и вклады в изменение за это окно. Не сдвигай период молча. Выгрузка доступных записей допустима. complete/has_more описывают передачу строк API, а не полноту исходной статистики. Nowcast не заполняет пробелы факта в сопоставлении; оценки физических показателей Comtrade сохраняют источник и не являются nowcast проекта.


### Направление торговли и полнота ответа (19.10.2026)

Направление задается относительно России: импорт Китаем или Индией из России соответствует `ex`/`ЭК`; импорт России из этих стран соответствует `im`/`ИМ`. Инструмент `resolve_trade_route(origin, destination, question)` сверяет маршрут с дословным вопросом. `UNKNOWN` означает неуказанную сторону, `WORLD` - всех доступных партнеров. База не описывает весь импорт третьей страны из мира: такой вопрос требует уточнения. В смешанном запросе нужно показать доступную российскую часть.

Усечение результата инструмента и пропуски в исходной статистике различаются. Неполный технический ответ получает `result_status=needs_refinement`; его строки не используются для итогов. Агент должен увеличить лимит, агрегировать данные или запросить ограниченные срезы. Успешные результаты других вызовов остаются пригодными для ответа. Помесячные запросы `trade` сохраняют измерения `type` и `source`, чтобы факт и nowcast не складывались незаметно.


### Обязательная проверка числовых выводов

Перед публикацией числового анализа внешний агент обязан вызвать `verify_trade_answer(draft, evidence_ids)` и получить `valid=true`. Используйте готовые расчеты сервера: суммы, динамику, экстремумы и таблицы. Модель выбирает существенные выводы, но не пересчитывает числа самостоятельно.

`trade`, `fizob`, `export_trade` и `product_overview` возвращают `numeric_facts` и `evidence_id`, когда данные позволяют сформировать расчетные фрагменты. Год к году сравниваются одинаковые месяцы; факт, источник и nowcast сохраняются раздельно. Пропуски не заменяются нулями. Индексы не суммируются.

Порядок работы:

1. Получить данные, выбрать подходящие фрагменты `numeric_facts` и сохранить `evidence_id` каждого использованного ответа.
2. Составить черновик с отдельными абзацами `{{fact:ID}}`. ID берется из ключей `numeric_facts`; ссылка вставляет готовый текст или таблицу целиком. Вне ссылок допустимы краткие заголовки и связки без числовых выводов и утверждений о направлении динамики. Начинать с сути для аналитика, ограничения выбирать по делу.
3. Передать черновик и список идентификаторов в `verify_trade_answer`. При `valid=false` исправить ошибки из `errors` и повторить проверку. При недоступном evidence повторить запрос данных. Отклоненный черновик не публиковать.
4. При `valid=true` передать пользователю поле `answer` без изменений. Дополнительная редактура моделью после проверки недопустима. Для нового расчета или уточнения пройти проверку заново.

Пример подготовки вызова в клиенте (идентификаторы берутся из реального ответа `trade`):

```python
facts = result["numeric_facts"]
selected = [key for key, fact in facts.items() if fact["kind"] == "total"]
draft = "Итоги по доступным данным\n\n" + "\n\n".join(
    "{{fact:" + key + "}}" for key in selected
)
arguments = {"draft": draft, "evidence_ids": [result["evidence_id"]]}
# Вызвать MCP verify_trade_answer с arguments и разобрать JSON результата.
# Публиковать checked["answer"] только при checked["valid"] is True.
```

В собственном MCP-клиенте проверку нужно закрепить программно: отсутствие успешного результата блокирует публикацию числового черновика и возвращает агент к проверке. После повторного отказа или сбоя следует сообщить о невозможности проверить соответствующий вывод, сохранив уже проверенную часть. Не выдавайте это за отсутствие исходных данных. Резервируйте шаги агентного цикла на проверку и исправление.

`compare_trade`, `explain_trade` и `rank_trade` дают готовые специализированные расчеты, но их ответ без `numeric_facts`/`evidence_id` сам по себе не проходит этот протокол. Для проверки поддержанных выводов запросите соответствующие срезы через `trade`/`fizob`. Не придумывайте ссылки на факты и не называйте проверенными расчеты, для которых верификатор пока не предоставляет фрагмент.

Evidence хранится в памяти до 30 минут и привязан к ключу доступа. Перезапуск или вытеснение из ограниченного кэша требует повторного чтения данных. Верификатор проверяет соответствие текста расчетным фрагментам; он не подтверждает правильность выбранного агентом маршрута или полноту публикаций источника. Эти условия проверяются при выборе данных.

В «Спросить ИИ» проверка обязательна на стороне сервиса; после неудачного исправления показываются готовые расчетные фрагменты. Во внешнем MCP-клиенте соблюдение протокола обеспечивает сам клиент: сервер не контролирует последующую редактуру ответа. Правила для агентов закреплены в [скилле trade-data](../.agents/skills/trade-data/SKILL.md).

### Обзор товарной группы и поиск по названию

Для общего обзора используйте `product_overview(code="6107", napr="im")`. Он возвращает официальное название, стоимость по доступным партнерам, основные страны-партнеры и их доли, годовую динамику и вклады стран. Динамика рассчитывается только для одинаковых стран и источников с известной стоимостью за каждый месяц обоих окон. Доля покрытия этого сопоставления показывается отдельно. Нулевая запись считается наблюдением, пропуск не заменяется нулем. Прогнозы проекта исключены.

По умолчанию выбран январь - последний доступный месяц базы. Можно задать `period_from` и `period_to`, до 12 месяцев. Денежный масштаб выбирается по величине показателя. Расчеты совпадают с обзором в «Спросить ИИ». Обязательная публикационная проверка: `verify_trade_answer` с `numeric_facts` и `evidence_id` этого обзора.

Свободное описание товара сначала передайте в `search_products(query="мужское трикотажное белье")`. Поиск возвращает кандидатов из русского справочника уровней 2, 4 и 6 знаков с названиями и родительскими кодами; параметр `level` ограничивает уровень. Совпадение слов не доказывает правильность классификации. Агент выбирает уровень по смыслу: широкая глава - 2, товарная группа - 4, конкретный подтип - 6 знаков. При неоднозначности он уточняет материал, назначение или исполнение товара. Например, «белье» без уточнений нельзя автоматически приравнивать к 6107. Не складывайте родительские и дочерние группы.

### Отдельная динамика при неполном периоде

Обзор показывает общий годовой темп по странам с полным одинаковым окном двух лет. Для остальных стран доступен отдельный расчет по пересечению месяцев с известной стоимостью и одинаковым источником. В ответе перечислены фактически сопоставленные месяцы: разрывный набор не выдается за непрерывный период. Эти индивидуальные темпы не входят в общий темп и не усредняются между странами. Нулевая база не дает процентного темпа; нулевая запись остается наблюдением. Основной ответ показывает до пяти стран с отдельной динамикой, по доступной стоимости текущего окна.

В MCP отдельные сопоставления доступны в `partial_country_comparisons` и проверяемом фрагменте `overview_partial`. Используйте его вместе с основным темпом, не пересчитывая числа. Термин «страны-партнеры» обозначает страны, а не компании. Полное название товара и источники вынесены в раскрывающийся блок.


## Подача ответов и fizob (20 октября 2026)

Структура зависит от задачи: выгрузка дает краткое резюме и файл; динамика -
изменения на сопоставимых периодах; объяснение - вклады подкатегорий; сравнение -
общий период. Уточнения сохраняют срез из истории, но не разрешение на новый файл.
Структурный вклад не доказывает экономическую причину изменения.

`fizob` автоматически запрашивает предыдущие 12 месяцев для г/г. В проверяемых
фактах показан индекс «первый доступный месяц = 100», изменение между концами
окна и отдельно календарные темпы г/г. Внутренний масштаб `idx` не предназначен
для пользовательского текста. Формула исходного индекса не меняется.
Выбирать `index_change`, `index_yoy`, `monthly_table`, `index_methodology`;
при наличии обязательно учитывать `index_caveat`. При нулевой/неизвестной базе
темп не рассчитывается, пропуски не заменяются нулем. Новые факты проходят тот
же `verify_trade_answer` / внутренний валидатор демо.

Ограничения указываются для затронутого показателя: неполная масса не отменяет
стоимость. Nowcast проекта отделяется от оценок источника UN Comtrade.
Резервный ответ демо собирается из проверенных фактов по задаче и проходит
валидацию. Обрезанная генерация не публикуется как законченный ответ.
